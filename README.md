# Raiders Have Families v0.6.0 — RimWorld 1.7 (полный накопительный пакет)

**Экспериментальная исходная версия для сборки в GitHub Actions.** Никаких утверждений о стабильности до запуска в игре. Сохраняйте резервную копию сохранений.

## Главное изменение — переговоры

Больше нет отдельной кнопки «связаться с родственниками» на консоли. Выбирайте **обычное «Связаться с [фракция]»**, затем колонист подойдёт к консоли и откроется стандартный `Dialog_Negotiation`.

Внутри **именно этой фракции** появится «Обсудить возвращение удерживаемых пленников…», если в ней есть отслеживаемые пленники. Далее: выбрать человека → подтвердить жизнь / обсудить выкуп / сообщить о медицинских операциях / отказать в возвращении. Это штатное дерево `DiaNode` с разветвлениями, а не мгновенные всплывающие окна.

- Доступность разговора и поход к консоли контролирует сама RimWorld; обходных кнопок нет.
- Перечень пленников **без преждевременного раскрытия цены**. Цены показываются при обсуждении условий.
- «Повышенное требование» означает **цену в серебре**, примерная вероятность согласия показывается отдельно в `%`.
- При принятии условий всплывает малое уведомление; оплата только после физического выхода пленника с карты.
- Полученная серебряная награда появляется возле точки выхода и сопровождается **кликабельным уведомлением** для перехода к ней. Если невозможно разместить награду там, попытка делается около центра карты.
- При безвозмездном освобождении +goodwill ограничен игровой шкалой и постоянными врагами. Если фракция `permanentEnemy`, обычный goodwill не изменится; применяется внутреннее изменение отношения RHF (влияет на расчёт переговоров). Это сообщается явно.

## Здоровье и операции

- Отдельный обработчик `RecipeWorker.ApplyOnPawn` регистрируется для обнаруженных вредоносных операций WCE2 и потенциально подходящих **ванильных** хирургических операций удаления органов. Обработчики регистрируются **один раз**, при запуске. Нет опроса здоровья каждый тик.
- Для WCE2 использована карта 60 рецептов из предоставленного архивного мода; 20 операций снятия имплантов / обратных вмешательств не трактуются как пытка. Поддержка WCE2 — опциональная. Его собственная совместимость с RimWorld 1.7 **не подтверждена** (архив содержит до 1.6).
- Регистрируются последнее название операции, количество, тяжесть. **Боевые ранения до плена не считаются пыткой**. При наличии новых отсутствующих частей тела без записи операции выводится формулировка «источник не подтверждён»; это честное ограничение, а не обвинение без доказательств.
- После публичного раскрытия через радиопереговоры применяются последствия для обычной репутации, внутреннего учёта RHF и подходящих колонистов (WCE2-принцип пытки/черта «Кровожадность»). Старые воспоминания RHF заменяются новыми. Если нового зарегистрированного события нет, бонус не выдаётся.
- В меню Ideology для поддерживаемых принципов добавлено **пояснение**, какие дополнительные эффекты реализует RHF. Действие каннибализма за публичное издевательство остаётся незавершённым и так и помечено.

## Тестирование — отдельные разделы

В режиме разработчика поиск `RHF` показывает категории:

- **RHF - ТЕСТЫ | РЕЙДЫ:** 15+ сценариев спасения и мести, существовавшие в v0.3.1, с их ограничениями и экспериментальным ИИ.
- **RHF - ТЕСТЫ | ПЛЕННИКИ:** 9 инструментов создания пленника **в клетке следующего щелчка на карте**, ранги от 0 до 8. Ранг является **тестовым RHF-значением**, не превращает пешку в фактического лидера фракции.
- **RHF - ТЕСТЫ | ДИАГНОСТИКА:** проверка ранга и связей, дополнительных родственников, числа медицинских Harmony-хуков, записей операций и проверка последствий сообщения. Команда симуляции операции создаёт запись, **не наносит физического вреда**, и предназначена исключительно для теста дипломатии.

## Система связей и рангов

Из v0.4.0 включены более плотные родословные с подтверждённым происхождением созданных модом связей, ранги 0–8, их отображение на вкладках «Персона» / «Пленник» и в подробной информации. Эти возможности **ещё не подтверждены игровыми тестами**, хотя их исходники включены в пакет.

## Производительность

Никаких Harmony-патчей обычных игровых тиков. Для семей — ограничение числа создаваемых мировых пешек; для спасательных рейдов — ограниченные очереди. Медицинские события обрабатываются только при фактическом выполнении соответствующих операций; проверка дипломатических сроков — разреженная.

## Что не готово / риск

- **Настоящий VIP-эскорт с прибытием через сутки, выплатой под ногами эскорта** ещё не реализован. Обычный выкуп выплачивается при выходе с карты.
- Полная постройка десантной капсулы спасателями, полноценные коалиционные армии и квесты вывода чужого пленника из поселения остаются экспериментальными/не реализованными как ранее оговорено. Не называйте их полноценными без игрового теста.
- Нельзя гарантировать совместимость со всеми модами, особенно с модами, заменяющими `FactionDialogMaker`, хирургические рецепты или генерацию пешек.
- Не собрана локально DLL: `dotnet` и нужных игровых DLL в текущей среде нет. GitHub Actions должен подтвердить компиляцию `.NET 10` и создать ZIP. **Не устанавливать исходный ZIP напрямую в игру.**

## Установка через GitHub Desktop

1. `Pull origin` → `Repository → Show in Explorer`.
2. Распаковать весь ZIP **в корень репозитория**, сохранив `RaidersHaveFamilies/Source/`, `.github/workflows/`, `tests/`.
3. `Commit to main` → `Push origin`.
4. Открыть Actions, скачать `RaidersHaveFamilies-RimWorld-1.7-v0.6.0-COALITION-TEST` **только при зелёном статусе сборки**.
5. Заменить старый мод, не оставлять старые DLL. На отдельном сохранении проверить консоль → выбранную фракцию → пленника → разговор → фактическую выплату, затем WCE2 и тестовые рейды.

При красном крестике пришлите ссылку на workflow/job или текст ошибки, а при ошибках в игре — `Player.log`.

## v0.6.0 — немедленные тесты, совместные рейды и объединённый патч

Это **полный накопительный исходный пакет**: включает v0.3.2 (подсказки принципов Ideology), v0.4.0 (плотность социальных связей, авторство связей, ранги и отображение в «Персона»/«Пленник»/инфокарте), v0.5.0 (настоящая радиосвязь с фракцией, разветвления разговора, хирургические доказательства, goodwill, уведомления о выкупе) и текущую переработку рейдов.

### Изменения рейдов v0.6.0

- **Тестовые команды создают рейд сразу при выборе** через `RaidEnemy.Worker.TryExecute`. Старый `incidentQueue.Add(..., now+150, ...)` для тестов убран. Если генерация рейда отклоняется, показывается прямое сообщение; при отказе модовой фракции однажды пробуется другой враждебный исполнитель.
- **Обычные (естественные) ответные операции** готовятся приблизительно 5000 игровых тиков; это не задержка отладочного действия. Они также используют единый новый запуск рейда в момент наступления события, а не «потерянный» инцидент в очереди.
- Операция может включать **от 1 до 4 фракций-заявителей**, чьи пленники удерживаются игроком, и **одну наёмную фракцию**, у которой вообще нет пленников. Дополнительные важные пленники (ранг от 5) других фракций могут стать причиной коалиции.
- **Комбинированное нападение:** реальные рейдовые группы имеют роли `Rescue` (идут к тюрьме), `Diversion` (ванильный ИИ отвлекающей атаки) или `Vengeance` (карательное нападение). Одна и та же фракция может прислать две группы с разными задачами. Вариант с наёмниками позволяет совместить прорыв/штурм и десант.
- Реальные партии создаются по одной, с **общим, а не умноженным** бюджетом угрозы. Максимум 5 партий в операции, 4 активных операций на карту, 96 NPC на каждую из групп-ролей; контроллер спасателей продолжает делать ограниченные решения раз в 300 тиков.
- Для тестов добавлены команды одновременного удара одной фракции, 3+ фракций-заявителей, операции с наёмным отвлекающим отрядом, смешанного прорыва с десантом. В разделе пленников есть клик-спавн VIP следующей ещё не представленной фракции; в диагностике — состав групп и отмена только сценарных контроллеров.

**Важно о границах:** отдельные реальные группы нескольких фракций создаются, но ванильные правила взаимной враждебности между этими фракциями пока не подавляются. Если участники враждуют друг с другом, они могут вступать во взаимный бой; полноценная безопасная дипломатическая кооперация ещё требует отдельного игрового решения. Точная тактика, эвакуация раненых, физическое строительство настоящих подов, коалиционная дружба, VIP-эскорт и квесты освобождения из чужих поселений **не являются завершёнными**. Не выдавать эту экспериментальную версию за релиз.

### Проверка

1. GitHub Desktop → Pull origin → Repository → Show in Explorer → распаковать **содержимое этого полного ZIP в корень репозитория** → Commit → Push origin.
2. Дождаться (самостоятельно на странице GitHub) результата `Build Raiders Have Families 0.6.0`. Скачивать только зелёный артефакт `RaidersHaveFamilies-RimWorld-1.7-v0.6.0-COALITION-TEST`.
3. В игре: подготовить пленника, вызвать «Rescue: breach and escape». Отряд должен появиться **сразу**, без 150 игровых тиков. Если не появился — открыть лог и диагностическую команду `17`.
4. Повторить: `CombinedSingle` (спасатели+лобовая атака одной фракции), `CoalitionHiredDiversion` (пленник одной фракции плюс наёмная сторона), после создания двух дополнительных VIP разных фракций — `CoalitionManyFactions`.
5. Проверить независимо все функции старых патчей: три места показа ранга, число/авторство отношений, диалог фракции с подходом к консоли, хирургические записи и goodwill, уведомление с точкой получения серебра.

**Компиляция и TPS:** статические Python/XML/лексические проверки не заменяют сборку DLL под RimWorld 1.7 и игру. В этой среде нет .NET SDK; GitHub Actions и внутриигровые тесты обязательны. Реальные показатели TPS не измерялись.
