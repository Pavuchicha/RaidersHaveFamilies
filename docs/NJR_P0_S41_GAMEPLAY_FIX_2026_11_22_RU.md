# NJR — Not Just Raiders | P0: исправления по живым тестам 01/16

**Основание:** локальный архив исходного GitHub-репозитория пользователя (NJR v0.14.0-beta2 + ранее подготовленные P0), скриншоты игрового тестирования 22.11.2026.
**Статус:** исходники и проверки. НЕ подтверждено реальной компиляцией DLL в этом окружении и реальными игровыми тестами после изменения.

## 01 — Спасение (наземная группа)

1. `RHFRescueGroundEntryS41`: точка появления обязана иметь открытый участок с проверенной локальной связностью и проходимый маршрут **без разрушения природных стен** к открытому подходу около места содержания пленника. `TraverseMode.PassAllDestroyableThings` исключён из проверки входа; случайный запасной спавн из предыдущего P0 не возвращался. Если доказуемого подхода нет — рейд явно отклоняется, а не появляется в пещере вне карты задач.
2. `RHFObjectiveRouteV128`: стоимость прохода через стену заметно выше стоимости доступа через дверь. Вступающий отряд не должен атаковать ближайшую стену при наличии разумного пути к двери.
3. `RHFObjectiveRouteV128` + `RHFRescuePlannerS41`: запрет на непроверенный прямой бросок через видимые сектора турелей, включая путь присоединения к основному маршруту. Цена маршрута учитывает турели; fallback не должен обходить запрет.
4. `RHFRescueRoleJobGiverS41`: освобождённый пленник **следует за реальным эскортом**, а не независимо бежит к далёкой точке выхода. `NJRRescueExitS41`: точка отхода выбирается один раз для пары/группы, проверяется доступность всех мобильных освобождённых и оценивается видимая опасность вдоль направления отхода.

## 16 — VIP, десант, укрепления и капсула

1. `RHFOperations.RescueDropCenter`: места высадки исключают клетки с мебелью, зданиями и пешками; потребная вместимость определяется бюджетом прибывающей группы, а не пустым `op.Squad` до фактической высадки. **Ограничение:** ванильный `CenterDrop` сам выбирает конкретные клетки разлёта, и отсутствие повреждений на 100% может подтвердить только игра/переход к собственному arrival mode.
2. `RHFVipEvacS311`: удалено активное уничтожение стен на строительной площадке. Сначала должны быть полностью построены реальные `PodLauncher` и `TransportPod`, и только потом инженер может быть отвлечён на строительство настоящих стальных стен через Blueprint/Frame/WorkGiver.
3. `NativeFortificationWorkS41`: в приоритете свободная клетка **с внутренней стороны реально смежной двери** в другую комнату, ограниченная с противоположных сторон твёрдыми стенами. Убраны «декоративные» случайные баррикады. Нельзя блокировать доступ VIP к капсуле либо последний локальный физический выход бойцов.
4. Зависшее `WorkGiver` фиксируется в логе с этапом/рабочим/выполняемой работой/материалами. После ограниченного отсутствия доступной строительной задачи и при отсутствии груза на бойцах — честный переход к наземной эвакуации без объявления о ложном запуске капсулы.

## Имя мода и совместимость

- GitHub Actions теперь упаковывает установленный мод в папку **`NJR-NotJustRaiders`**. Именно эта папка появится в `RimWorld/Mods` после новой успешной CI-сборки.
- **Не переименованы:** `packageId=pavuk.raidshavefamilies`, DLL `RaidersHaveFamilies.dll`, C# namespace, Scribe и DefName. Это сознательная совместимость с сохранениями. Папка с исходниками внутри GitHub также остаётся `RaidersHaveFamilies`.
- При установке нового артифакта **удалить прежнюю папку `RimWorld/Mods/RaidersHaveFamilies`**: нельзя ставить одновременно две копии одного packageId.

## Проверка и критерии результата

1. CI: все статические Python-гейты зелёные, .NET 10 компилирует DLL, release ZIP содержит `NJR-NotJustRaiders/About/About.xml` и `NJR-NotJustRaiders/Assemblies/RaidersHaveFamilies.dll`.
2. Сценарий 01: группа появляется в реально доступной наземной зоне; не остаётся за скалой; маршрут выбирает дверь при разумной возможности; избегает видимых турелей; при фактическом освобождении VIP и эскорт движутся в одну сторону и физически покидают край карты. Провал/отступление регистрируется без фальшивого успеха.
3. Сценарий 16: падение капсул не уничтожает мебель без физической необходимости; выстраиваются оба реальных сооружения с ресурсами и работой; защитные стены появляются у дверных подходов (только когда геометрия и резервный выход это позволяют); VIP реально оказывается в `CompTransporter`, затем запускается реальный полёт. Если стройка невозможна, отряд не остаётся навсегда в фазе ожидания.
4. Дополнительные повторные тесты 02, 09, 15, 17 и Save/Load, поскольку изменены общие механизмы.

**Не объявлять gameplay PASS по структурным тестам.** При новом сбое нужен полный `Player.log`, номер сценария, активная фаза операции, положение пленника и скриншот. Агент А получает отдельный файл задач; работа агента не была автоматически исполнена через этот архив.
