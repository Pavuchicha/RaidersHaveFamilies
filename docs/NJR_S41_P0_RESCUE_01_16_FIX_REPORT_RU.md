# NJR S4.1 P0: спасение 01 / VIP 16 — рабочий пакет исправлений

**Источник:** архив пользовательского GitHub-репозитория `RaidersHaveFamilies(1).rar`.
**Базовый коммит:** `e4e6c6871f214574417819f74a676f82b8ff81f2`.
**Формат:** overlay ZIP: полные заменяемые файлы для корня репозитория. **Не установочный ZIP для игры**.
**Итог:** исходники изменены. Python-контракты и лексические тесты пройдены. **Компиляции DLL и проверки в RimWorld здесь нет**.

## Что изменено

1. **Вход обычного спасения:** собственный проверенный `spawnCenter` сохраняется для повторной попытки; исключён скрытый возврат к произвольной окраине/пещере. При отсутствии верифицированной доступной точки тест сообщает об отказе вместо фальшивой успешной операции. Сканирование периметра стало плотнее. Это компромисс: крайне закрытая горами карта может не дать спавн вместо неправдоподобной телепортации.
2. **Движение штурмовой группы:** ведущим становится ближайший активный свободный боец, а не первый элемент списка. Если дорогой маршрут не найден, планировщик ограниченно ищет физически доступный промежуточный сборный пункт. Это убирает часть случаев массового `Hold` на краю карты, но ещё не заменяет полноценный игровой тест на конкретном сейве.
3. **Площадка VIP:** площадки, требующие предварительного пролома стен, исключены из первичного выбора; размещение в комнате пленника сохраняет приоритет. Пятитиловая запретная зона для снятия тонкой крыши уменьшена до трёх клеток при сохранении запрета на толстую крышу. Временных бойцов собственного спасательного Lord больше не считают несдвигаемыми препятствиями при поиске площадки.
4. **Строительная доставка:** носильщики не сваливают железо и компоненты на фактическую площадь пусковой установки/капсулы.
5. **Охрана и VIP:** прежние действительные позиции охраны сохраняются при перепланировании; позиции исключают строительные пятна. Назначенная точка ожидания VIP не пересчитывается при каждом перемещении пешки.
6. **Баррикады:** приоритет у защищаемых узких проходов с настоящими соседними стенами и дверьми, а не у декоративных точек на открытом полу. Дорогие проверки пути запускаются только после дешёвых геометрических фильтров. После завершения реальной стены лимит времени на основную стройку запускается заново.
7. **Регрессии:** тесты, которые буквально требовали прежнего случайного повторного спавна, обновлены. Добавлен `tests/njr_203_p0_rescue_entry_pod_site.py` в CI.

## Что не подтверждено

- Настоящая работа каждого Pawn Job и Lord при RimWorld 1.7 + CE/WCE2.
- Эвакуация VIP физической капсулой, материалы, крыша и перелёт на всех планировках.
- Что каждый из пяти бойцов нанесёт урон: роль боевого прикрытия не обязана стрелять, если нет физически доступной цели.
- Что на каждой планировке найдётся узкий коридор для 1–2 стен: недопустимая декоративная баррикада теперь не возводится.
- Полная тактическая успешность остальных 16 сценариев.

Эти ограничения не должны быть описаны как исправленные до настоящего игрового теста.

## Проверка на сборке

1. После замены файлов запустить GitHub Desktop → Commit to main → Push origin.
2. GitHub Actions → последняя сборка → дождаться **зелёного** выполнения тестов, компиляции DLL и проверок install ZIP.
3. Скачать артефакт `NJR-NotJustRaiders-RimWorld-1.7-v0.14.0-beta2` последней **зелёной** сборки. Заменить одну установленную папку `RaidersHaveFamilies` в `Mods`; не оставлять две копии.
4. В новом тестовом сохранении запустить **01** с пятью бойцами и **16** с VIP в камере, где реально помещается физическая установка. Убедиться, что сооружения возводятся в игре, а не просто числятся в планах.
5. Если №01/16 остаётся нерабочим, нужны `Player.log` и разработческий отчёт **36 — S4.1 Blackboard, роли, приказы** в момент остановки.

## Совместимость

`packageId`, имена классов и сборки, Scribe-ключи и DefNames не изменены. Изменения относятся только к управлению операцией и тестам. Сохранение в середине уже запущенного рейда лучше не использовать для проверки новой логики.

## Отдельные изменения, уже имевшиеся в присланном RAR

Внутри пользовательского репозитория были изменённые файлы в **корне** (`About.xml`, `RHFOperations.cs`, `RHFPatches.cs`, `build.yml` и др.), отличные от реальных файлов в `RaidersHaveFamilies/Source` и `.github/workflows`. Этот overlay **их не содержит** и не исправляет. В GitHub Desktop перед коммитом проверьте, чтобы посторонние старые изменения не попали в новый коммит случайно.
