Нельзя утверждать, что именно один из этих фильтров вызвал все десять отказов — прежний журнал не содержит причин по каждому кандидату.

## Изменения
- Для VIP отдельный обратный door-only поиск использует тот же проверенный основной алгоритм, отдельный кэш/фронтир. Прямой поиск также сохраняется; независимая попытка нативного PassDoors через FindPathNow (при наличии enum и списка узлов), с проверкой каждой клетки, реальными HP, отклонёнными препятствиями и ценой угрозы. Незавершённый поиск не является разрешением на разрушение стены. Короткая повторная проверка перед первым fallback, повторное планирование ещё не атакованной стены. Лог DoorGrid содержит фактическую локальную матрицу разрешённых клеток в момент отказа. Нельзя считать это гарантией доступности нативного API или исправления игрового поведения.
- VIP exit: целевая граница согласована с принятой системой (0/1); независимый поиск двери FirstBlockedExitDoor из Rescue-1 применяется до разрушительного fallback. Если проверенная дверь не имеет доступного места для удара, это не разрешение на угол. Повторная проверка до fallback. Собственное заграждение по-прежнему допускает физический Deconstruct.
- Реальный проход выбирается отдельно от логистики, крытая геометрия и рабочие клетки вместо строгого равенства Room на impassable pad. Груз за границей кармана или в клетке будущей стены получает физическую переноску отдельным бойцом с нативными hauling toils, а не телепортируется. Учет переносимых/разделённых стеков. Выгрузка в защитном кармане, избегание горловин. Охрана освобождает место стройки, строители и заправщик не назначаются перевозчиками. Заграждение только через реальный Wall blueprint, затем Frame и Wall. При невозможности безопасного переноса заграждение не строится, запуск не блокируется.
- Не изменены выбор крытой площадки, бюджет/генерация инженеров, запуск, боевая/CE-механика. Не менялась целенаправленно принятая ветка №1; общие helpers затронуты, проверка регрессии желательна.
