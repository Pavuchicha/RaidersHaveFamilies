# NJR — Not Just Raiders · сквозная ревизия / v0.14.0-beta1

**База:** накопленный кандидат RHF S4.1-A/P (содержит S4.1-A/O); первоначальный опубликованный `main` `1b17a0c635ede9e164ccd7a9b37ed1a5535101fa` — S3.1.2. Последний подтверждённый успешный GitHub Actions для предыдущей S4.1-A/O: run `45056773643` (`s4.1-test`, `12ebe01ffe99ba72dbcaec7b73e011db5b8dde1b`). Новая v0.14.0-beta1 ещё **не компилировалась и не тестировалась в игре**. Это принципиально важное разграничение.

## I. Название и совместимость

Официальное отображаемое имя: **NJR — Not Just Raiders**. Удалены избыточные кавычки вокруг *Just*: по-английски «Not Just Raiders» естественнее, и смысл «не просто рейдеры» сохраняется. Сокращение `NJR` тоже нормально.

Сохранены `packageId=pavuk.raidshavefamilies`, путь установки `RaidersHaveFamilies`, C# namespace, `RaidersHaveFamilies.dll`, сериализуемые ключи и существующие `RHF_*` DefNames. **Это сознательное решение:** массовое механическое переименование классов, DefNames или ID ради бренда сломало бы ранее сохранённые игровые ссылки и совместимость с модами.

Изменены отображаемые имя, описание RU/EN, категория настроек, меню разработчика, UI-подписи рангов, описания Ideology с миграцией старого маркера, README, имя CI-задачи, ZIP и артефакт выпуска. Корневая папка репозитория на GitHub пока остаётся `RaidersHaveFamilies`; её смена — отдельное действие в настройках GitHub после подтверждения стабильности сборки, а не обязательное условие появления нового названия в игре.

## II. Что реально проверено

- Прочитана и объединена полная рабочая база S4.1-A/P: **40 файлов C#** и **12 XML**, включая все игровые Defs и метаданные.
- **58/58 локальных статических тестов:** 57 накопленных RHF + новый `tests/njr_200_integrity_audit.py`. Проверяют специфические контракты операций, семей, дипломатии, логики пленников, коалиции, новых инженерных и воздушных процессов, а также единственность 18 отладочных сценариев и совместимость ключей.
- Проверены все 18 `RHFDebugScenario`, по одному обработчику запуска, без повторяющихся номеров; XML загружаются, локальные DefNames уникальны, наборы английских/русских текстовых ключей совпадают.
- Исключены определения взрывного комплекта пролома (оставлены пустые совместимые XML), неподдерживаемая роль мгновенного урона и конфликтное выдавание старых заданий.
- Удалено неиспользуемое поле `LastCohesionTick`, вызвавшее `CS0649` в прежней настоящей компиляции.
- Добавлены отдельные проверяющие этапы GitHub Actions: `njr_200_integrity_audit.py` до компиляции и `njr_201_release_zip.py` **после** сборки установочного ZIP. Второй проверяет CRC ZIP, подлинную PE/MZ DLL, структуру `About`, `Defs`, локализации, сохранённый `packageId` и отсутствие исходников в дистрибутиве.
- Аудит проверяет **структуру и статические контракты**, а не работоспособность в игровом потоке, CE pathfinder, кадровую производительность, конкретные раскладки оружия или правильность `Lord` после Save/Load.

| 02 | Группа пленников | Не подтверждено | Конвоиры, независимые цели, выход последнего VIP |

| 05 | Наёмники | Не подтверждено | Совпадение роли, лояльности и фактического владельца `Lord` |

## IV. Системные подсистемы

| Подсистема | Состояние | Уязвимости / границы уверенности |
|---|---|---|
| Семьи, социальные связи, лимиты `WorldPawns` | Контракты статически проходят | Статус по длительной игре и большому числу фракций не верифицирован |
| Ранги и диалоги с фракциями | Исторические тесты проходят | WCE2/Ideology и неизвестные модовые фракции могут вести себя иначе |
| Плен, продажа, пытки, Ideology | Контракты статически проходят | Важна проверка дисклозера только после фактического события, без дублирования memories |
| Враждебные фракции и коалиции | Сохранены отдельные задачи и владельцы | Нужно проверить `Lord`/faction под реальными инцидентами |
| 18 рейдов и тактический поиск | Точки вызова и контракты проверены | Не равно 18 успешным боевым AI; нужны игровые ситуации |
| Двери и проломные топоры | Удалён бесплатный breach kit; используется vanilla melee | Снаряжение и реальные атаки после S4.1-A/O требуют игрового подтверждения |
| Капсулы и фортификация | Проект, материалы в инвентарях, инженер, VIP, посадка, Skyfaller/world transport | Реальная цепочка наблюдалась лишь для одного случая; фортфикации/ретаргет на дальнее поселение могут требовать исправлений |
| Save/Load | `packageId`/C# классы/Scribe остаются | Реальное сохранение в стадии 3, 5 и в мировом полёте не проверено |
| Combat Extended | Сохранены защитные контрактные проверки | TPS, баллистика/подавление и взаимодействие CE в игре не подтверждены |
| Производительность | Есть event-driven/разреженные обработчики и лимиты | Численные показатели TPS отсутствуют |

## V. Что специально НЕ делалось

1. Массового переименования namespace/assemblies/DefNames, разрушившего бы сохранения.
2. Подмены реального компилятора Python-проверками.
3. Выдачи 18 структурных сценариев за 18 подтверждённых игровых тестов.
4. Переноса прежней S3.1.2 в `main` без изменений. Пакет собирается **как полный накопленный upgrade** поверх указанного SHA.
5. Удаления старых `RHF_ExtractionPod`/`RHF_FieldLauncher` DefNames — возможно, на них ссылаются старые сохранения; описания честно помечают их устаревшими.

## VI. Один короткий проверочный цикл после CI

**Сначала один Push в `main`, один GitHub Actions run.** Не устанавливать ZIP при красной сборке. При зелёной скачать **новый** артефакт NJR, удалить/заменить старую директорию в `Mods` (без дубликатов), создать тестовый сейв и прогнать в одном сеансе **01 + 16 + 02/06**. Для 16-го заранее подготовить индустриального VIP ранга 8. Сохраняться на разных фазах 16-го и загрузить. Проверить инвентари, владельца построек, реальные стены, вход в физическую капсулу, вылет. С CE запустить отдельный тест; если есть красные ошибки, приложить один полный `Player.log` и описание номера сценария. Это не замена полного регрессионного прогона 18 случаев перед релизом, но позволяет одним сеансом выявить основные высокорисковые регрессии.
