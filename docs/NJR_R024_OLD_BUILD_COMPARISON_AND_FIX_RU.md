# NJR R024 — сравнительный аудит маршрутизатора и исправление бесполезных разрушений

Дата: 23 ноября 2026. База R023. Контрольный билд предоставлен пользователем как `NJR-NotJustRaiders-RimWorld-1.7-v0.14.0-beta2 (1).zip` (внутри install ZIP с DLL и PDB, без C# исходников). Для сравнения исходного кода v0.14.0-beta2 дополнительно использован предыдущий коммит репозитория `e4e6c6871f214574417819f74a676f82b8ff81f2`, соответствующий этой версии.

## Что пошло не так

### 1. Выбор 3 стен вместо двери

В старой версии `RHFObjectiveRouteV128.Resolve` использовался один полный A* с одновременным учётом движения, HP препятствий и реальной опасности обстрела (ExposedCost=4000); алгоритм мог недооценивать альтернативы, но не навязывал абсолютного отсутствия турелей.

В R023 было до **трёх последовательных поисков**: без стен и без огня, затем с разрешёнными стенами, но по-прежнему без огня, затем рискованный. Это позволяло выбрать несколько уничтожаемых стен, если более подходящий вход был связан с коротким сектором обстрела. Высокий ExposedCost=12000 также искажал сравнение между реальной опасностью и длительной работой по разрушению прочных стен.

**R024:** один multi-source A*, без запрета проходить известные секторы огня. Стена — 7000 + 6*(16 + 2*текущие HP), закрытая дверь — 350 + 16 + 2*HP, передвижение — 10, экспозиция — 300 за подтверждённую живую угрозу с множителем важности (турель х2), до 4800 за клетку. Все варианты оплачиваются в одной сумме. Не гарантируется глобально кратчайший путь по геометрии: это минимум заданной тактической стоимости в пределах лимита поиска.

Вместо трёх полных поисков один ограниченный 30 000 раскрытых вершин. Остаётся риск нагрузки при особенно тяжёлых картах; реальные TPS не измерены.

### 2. Остановка перед полностью закрытой турелями базой

Раньше опасный коридор был стоп-сигналом, даже когда все подходы находились под огнём. Теперь если выбранный путь пересекает сектор турели, он явно помечен `RiskFallback`, который допускает движение и локальное подавление реально видимой турели. Старые ограничения безусловного ожидания сняты именно на активной линии планировщика S41.

### 3. Генераторы и другие ненужные здания

Прежняя `RequiresBreach` классифицировала любое разрушимое враждебное непроходимое edifice потенциальным проломом. Даже при наличии альтернативы такой объект мог попасть в маршрут и стать целевой постройкой.

**R024:** допуск к разрушению в наземной спасательной операции только для реальных дверей и конструкций, идентифицируемых как стена/ворота/баррикада (включая модифицированные defName, содержащие Wall/Gate/Barricade). Электрооборудование, генераторы, мастерские, мебель и все прочие edifice не являются правомерными целями пролома. Если неизвестная модифицированная блокировка не имеет такой идентификации, путь через неё будет считаться недоступным — это намеренная защитная политика и совместимость необходимо тестировать отдельно.

Строгая проверка действует **трижды**: в `Step` маршрута, в `Breach` роли перед выдачей job, в `ClaimGroup` перед сохранением атакующего job. `NJRCombatContactS44.BreachToward` вовсе не назначает альтернативных разрушений в миссиях спасения; для рейдов мести функция сохранена.

### 4. Отвлечение на посторонние турели и разрушения отвлекающего крыла

В R023 планировщик при отсутствии угроз на выбранном пути всё равно мог найти любую наблюдаемую турель и отправить к ней спасателей. В R024 фоновый выбор турели доступен только при НЕудаче поиска пути. При реальном попадании турели в выбранный путь назначается соответствующее подавление.

Отдельно в `RHFOffenseS41` отвлекающая группа спасательной операции больше не получает приказ разрушать произвольную инфраструктуру до успешного освобождения пленника; рейды мести и явно назначенная карательная фаза 5 сохраняют собственные разрушительные цели.

## Что изменено в C#

- `RHFObjectiveRouteV128.cs`: единый взвешенный A*, ограничение только физическими препятствиями, реальные затраты на двери/стены, ограниченный обстрел, переход под огнём, строгий whitelist проломов.
- `RHFRescuePlannerS41.cs`: подавление только турелей, действительно угрожающих выбранному маршруту; отсутствие искусственного ожидания перед выбранным рискованным проломом.
- `RHFRescueRoleJobGiverS41.cs`: проверка того, что выбранная постройка является допустимым проломом.
- `NJRCombatContactS44.cs`: запрет самостоятельного поиска стен для операций спасения; остальные наступательные рейды не затронуты этой функцией.
- `RHFRescueCommandV124.cs`: отмена неавторизованных атак по зданиям, которые не относятся к физическому пролому.
- `RHFOffenseS41.cs`: отвлекающая группа спасения не разносит инфраструктуру до завершения цели, при этом рейд мести сохранил своё назначение.

## Проверено

- 83/83 отдельных Python проверок, совпадающих со стадией `Verify metadata, source contracts, and budget invariants` в `.github/workflows/build.yml`, в четырёх отдельных пакетах. Отчёт в `docs/NJR_R024_CI_SOURCE_RESULTS.json`.
- Новая проверка `tests/njr_228_r024_old_beta2_weighted_rescue.py` формализует сценарий 3 стены **против 1 стены + 1 двери**, короткий сектор турели, полностью простреливаемую базу и недопустимый генератор. Это детерминированная графовая модель плюс проверки активных точек вызова, НЕ выполнение C#.
- Лексическая проверка исходников прошла.

## ЕЩЁ НЕ ПРОВЕРЕНО

- C# компиляция DLL в GitHub Actions (в локальной среде нет `dotnet` и референсов RimWorld).
- Реальные маршруты и TPS на пользовательской карте; соответствие модельных сценариев игровой геометрии.
- Спасение №16 (пусковая установка/капсулы) не изменено R024, проблема остаётся открытой.
- Выявленный whitelist модифицированных конструкций может потребовать расширения по фактическим `ThingDef` из установленных модов. Нельзя автоматически приравнивать генератор к стене.

## Проверка в игре

1. Установить R024 после успешного GitHub Actions и убедиться, что DLL действительно новая.
2. Провести спасение №1 на неизменной карте: 3 стены против 1 стены + дверь. Проверить выбор маршрута и реальную работу сапёра.
3. Включить VerboseLogging и проверить `[NJR][R021][SharedRoute]`: `doors`, `walls`, `expanded`, `cost`, `result=WEIGHTED-R024`.
4. Проверить базу с полным обстрелом: отряд идёт, отбивается, не получает вечный Hold только из-за турелей.
5. Проверить, что при спасении посторонний генератор и соседние стены не получают задачи `AttackStatic/AttackMelee`, а после контакта с пленником миссия переходит к освобождению и отходу.

Если ошибка повторится после именно этой DLL, нужны `Player.log` и диагностическая запись `[NJR][R021][SharedRoute]`, а также задания бойцов на момент разрушения. Результат игрового теста нельзя объявлять заранее.
