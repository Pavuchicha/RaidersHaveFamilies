# NJR R015 — последние правки перед игровым тестом (23.11.2026)

**Статус: исходный код, не проверенная игровая сборка.** R014 → R015. Проверять в RimWorld 1.7 только после успешного `.NET 10` билда в GitHub Actions; исходный GitHub ZIP не содержит готовой игровой DLL.

## Что действительно не работало правильно в R014

1. `NJROffensePathS45` рассчитывал маршрут с запретом известных огневых зон, но `RHFOffenseRoleJobGiverS41` отдавал `JobDefOf.Goto` в далёкую точку построения: ванильный pathfinder мог выбрать более короткий, **совсем другой путь через турели**, игнорируя расчёт A*. При разделённом отряде маршруты бойцов не соответствовали маршруту командира.
2. При отсутствии свободной позиции построения рядом с проломщиком или точкой атаки `PlanFaction` выставлял `order.Cell = soldier.Position`. Поскольку цель совпадала с текущим местом, защитник мог так и остаться стоять, хотя маршрут к товарищам существовал.
3. `NJRCombatContactS44.BlockingStructure` выбирал препятствие через `IsBreachableStructure`, которое считает открытые двери разрушаемыми. `NJROffensePathS45.Plan` останавливался рядом с любой клеткой, содержащей edifice, включая **открытую дверь**, вместо того чтобы пройти через неё. Похожие проверки были у штатного наступательного и спасательного `JobGiver`.
4. Аварийный `BreachToward` не проверял запрет на насилие и физическую манипуляцию: такая пешка могла многократно получать невыполнимое задание `AttackMelee`.
5. Позиция проломщика — **занятая клетка**, а не свободный слот; при неудаче поиска строя нужно двигаться до соседней клетки, а не пытаться встать в клетку, где находится товарищ.

## Изменения и API-верификация

Класс `Verse.GenGrid.Standable` проверен по [декомпилированному коду RimWorld](https://github.com/codexvn/RimWorldDecompiled/blob/master/Assembly-CSharp/Verse/GenGrid.cs): метод исключает некоторые проходимые клетки с постройками. Это подтверждает необходимость специального прохода через открытую дверь. Код внешнего проекта **не копировался**.


- `RaidersHaveFamilies/Source/NJROffenseRouteS45.cs`: `NextStep` — именно следующая соседняя клетка A*; открытая дверь учитывается как проходимая даже при `Standable=false`; цель, занятая другим бойцом, достигается через `Touch`-подход.
- `RaidersHaveFamilies/Source/RHFOffenseS41.cs`: собственный `FollowAssessedRoute` для каждого участника отряда на основании разведданных **своей** фракции; задания Goto только на соседнюю клетку, без перескока опасных углов; последовательный физический пролом при встрече барьера; динамический выбор цели присоединения, если построение не удалось; ни одного глобального патча ванильного Pathfinder.
- `RaidersHaveFamilies/Source/NJRCombatContactS44.cs`: не бить уже открытые двери, не выдавать аварийный пролом бойцам с запретом насилия и без манипуляции.
- `RaidersHaveFamilies/Source/RHFRescueRoleJobGiverS41.cs`: отмена пролома, когда дверь открылась и препятствия больше нет.
- CI `.github/workflows/build.yml`: R015 (`v0.15.0-beta1`) + сценарий `tests/njr_221_route_execution_r015.py`, 19 прежних release-name assertions обновлены **только** под новый выпуск. Ключи Scribe, namespace, packageId, старые имена DLL не менялись.

## Подтверждение и границы

Проверен исходный C# по перечисленным путям вызовов, индексы текущей позиции, типы задач и целевые условия, выполнены вспомогательные Python source/reference tests. Это **не** C# компиляция и не симуляция JobDriver; текущий игровой результат неизвестен. В среде подготовки отсутствует `dotnet`. Главный следующий технический рубеж — успешный GitHub Actions `Compile mod DLL` на ветке пользователя.

Особенность настройки производительности: при наступлении теперь возможен **полный A* для каждого бойца на каждое новое движение**, без искусственных лимитов. Пользователь сознательно предпочитает качество тактики TPS; риск серьёзных задержек на больших картах реален.

Не закрыто: игровые ошибки спасений №01 (неправильный спавн/бездействие) и №16 (высадка, разбор лишней мебели, строительство и баррикады), одиночный выкуп с потерей выплаты при сбое капсулы, реалистичное взаимодействие CE и больших коалиций. Никаких заявлений, что они решены, нет.

## Что тестировать первым на ПК

1. **Сначала** заменить исходники через R015 GitHub Desktop ZIP; commit/push, получить **зелёную сборку**. Если компиляция красная — взять ошибки первого C# error и исправлять их, не начинать игровой тест.
2. В RimWorld проверить только на копии сохранения. Включить Dev mode и `Debug actions menu` → категорию NJR → `01 — Спасение: пролом и побег`. В комнате пленника сделать выбор: три стены безопасно, две двери через видимые турели. Бойцы не должны уходить через прострел, когда есть оплаченный физический пролом. Убедиться, что *все* члены отряда двигаются и атакуют реальную угрозу.
3. Запустить `16 — VIP: десант, баррикады, полевая капсула`. Поддержка должна сдерживать врага, а инженер/снабженец продолжать реальную стройку и посадку VIP; не разрушать открытую дверь или мебель без тактической причины.
4. Отдельно: открыть дверь перед сапёром; закрыть её позже; убить сапёра; временно скрыть турель; сменить владельца турели; навести врага на конвой. При отсутствии преследования арьергард не оставлять.
5. При неудаче прислать: screenshot карты, `Player.log`, номер теста, **исходный и фактический результат**, скрин `GitHub Actions` (если красный). Игровые журналы важнее новых зелёных Python тестов.

## Не делать

Не распаковывать архив преемственности в папку мода/репозитория. Не ставить GitHub ZIP как готовый мод. Не смешивать установленную DLL от R014 с исходниками R015. Не создавать вторую папку NJR рядом с прежней — сначала резервная копия и удаление старой копии мода.
