# NJR R060 — единый бюджет фракции

База: R059. Правило пользователя от 22.11: стандартные очки угрозы игры; модификаторы важности пленника, числа пленников именно данной фракции и давления -100…0. Каждая отдельная фракция коалиции и отдельная наёмная фракция получают собственный полный расчёт. Внутренние группы одной фракции не создают дополнительного бюджета.

## Дефекты R059
- Debug DropRescueWithDiversion делил один бюджет между разными фракциями (58/42).
- Естественная месть без найденных наёмников и катастрофическая репрессалия могли удваивать бюджет одной фракции.
- Debug reserve мог наследовать агрегат всех фракций, а не свой бюджет.
- Подсчёт пленников по списку целей операции пропускал других живых пленников этой фракции на карте.
- Необязательные закупки могли оставить спасателей без денег на минимальную численность, даже когда исходный бюджет её позволял.
- Общая стоимость капсулы могла вычитаться у каждой спасательной группы при расчёте дополнительных бойцов.

## Исправление
`NJRThreatBudgetS41.AllocateOperation`: группировка по фактической Faction, один расчёт на группу, распределение по весам внутренних отрядов. Вызов при Register и перед Deploy, независимо от вида операции; ни одного нового расчёта в тактическом тике. Исправлены также исходные ошибочные ветви DebugActions, HostageSystems и Reprisals. Запасной debug-исполнитель получает только собственный расчёт; бюджетный отказ не вызывает резервную попытку. LiveCaptives использует реальную карту, живых пленников/рабов, исходную фракцию из реестра и дедупликацию. Ранг теста изменён на максимальный ранг целей/ранг перебежчика. Формула численных модификаторов R059 не изменена: это текущие параметры реализации, а не отдельно утверждённые пользователем числа.

Минимум спасательной группы в текущем коде — 5 бойцов. Сначала защищается цена пяти обычных фракционных бойцов, затем закупки. Если базового бюджета недостаточно даже для ядра, эта группа не отправляется (решение автора R060 для согласования минимума с запретом бесплатных очков, отдельно пользователем не утверждено). При дорогом выборе нативного генератора допускается замена не прибывших элитных пешек на более дешёвых бойцов того же Combat PawnKind, чтобы оплатить недостающий состав. Не гарантируется, что все модовые фракции способны сформировать его. При невозможности оплатить капсульный комплект сохранён наземный fallback R059. Для внутренних крыльев мести без наёмников выбрано 60/40; другие заданные пропорции сохранены. Стоимость капсульного комплекта вычитается у реально оплатившего его крыла (`PodCostR060`), не у остальных.

## Проверки и ограничения
117 команд предсборочного CI: 116 прежних + 1 новая. Из прежних 112 успешно завершились в общем прогоне; 4 с жёстко заданной меткой R059 обновлены на R060 и успешно перезапущены отдельно. Дополнительно перепроверены непосредственно изменённые естественные/отладочные ветви, структурные разделители C# и тесты бюджета. Это исходниковые и Python-проверки, не проверка исполнения C#. .NET SDK и RimWorld отсутствуют. Фактические расходы нативного генератора, сценарии с модовыми фракциями и CE, минимальный состав при реальном прибытии требуют игрового теста. Тактический ИИ, строительные задачи и отход не менялись. Оружейная фильтрация сигнальных пистолетов не входит в эту ревизию.
