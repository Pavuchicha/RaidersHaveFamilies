# NJR R007 — проверка совместимости и оптимизация фоновой нагрузки
Дата: 23.11.2026. Область: C# RimWorld 1.7, СТАТИЧЕСКАЯ проверка + модели. Никаких заявлений о GAME PASS / COMPILE PASS.

## Что обнаружено в R006, почему это важно

1. `RHFGameLedger.FindHostage` делал линейный перебор **всех** записей пленников. Патч `Pawn.ExitMap` вызывает его для всех уходящих пешек, включая тех, кто никогда не был пленником. С ростом числа сохранённых расследований и групповых договоров лишняя работа возрастала как O(H) на каждый выход. R007: неперсистентный `Dictionary<Pawn,RHFHostageRecord>`, отрицательный поиск в среднем O(1). Положительный поиск сохраняет проверку `Hostages.Contains(record)` ради корректности при редактировании публичного списка; по смыслу всё равно реже и безопаснее, чем линейный поиск для всех событий. Удаление/отвязка ссылки вызывает `InvalidateHostageIndex()`, который **немедленно очищает Dictionary** и не держит ушедшую пешку до следующей проверки. При PostLoadInit индекс не сериализуется и строится заново по старым Scribe-записям. Инвалидация добавлена ко всем местам собственного кода, где удаляют запись или отвязывают Pawn.
2. При массовом `Pawn.SpawnSetup` очередь `RHFMapComponent.Enqueue` определяла дубликаты `pending.Contains(pawn)` за O(Q) для каждой прибывшей пешки. R007: временный `HashSet<Pawn> pendingSet`, добавление в среднем O(1), сохраняющий старое ограничение `MaxBatchSize=192`; `pendingSet.Clear()` только при взятии партии в работу, после загрузки полностью пересоздаётся. Внутри боевого ИИ ничего не менялось.
3. Кандидаты животных модовых фракций в `NJRForceCompositionS42` каждый раз заново перечисляли `pawnGroupMakers`, строили новый список и выделяли до 48 временных списков допустимых видов. R007: кэш списка по `FactionDef`, включая пустые результаты; один `List<PawnKindDef>` переиспользуется в пределах одной генерации группы. Кэш действует только на статический Def, без сохранения в сейв. Если другой мод динамически меняет `pawnGroupMakers` уже после загрузки всех Def, кэш потребует обновления при отдельной интеграции; такого API в NJR пока нет.
4. Автовыдача `ArmorUpgrade` и `NJROrbitalSupportS42.TryIssue` могла надевать вещи несовместимого слоя, вызывая снятие экипировки, которую выдал сам `PawnKind` или мод CE/HAR/VE. R007: `NJRApparelCompatibilityS43.CanAdd` использует ванильный `ApparelUtility.CanWearTogether` для каждого существующего предмета. Если набор несовместим, ДО `ThingMaker/Wear` выдача пропускается. Ошибка модового хука совместимости изолируется, выдача пропускается, а не срывает рейд. При исключении во время Wear делается попытка снять необоснованно выданную вещь. Стоимость брони и орбитального целеуказателя теперь считается по **фактическому `MarketValue` созданного предмета**, только после успешного надевания; если итоговая цена выходит за лимит, предмет уничтожается до выдачи. В CE сохраняется запрет смены основного огнестрельного оружия без соответствующих боеприпасов.

## Совместимость — проверки и честные границы

| Среда | Что защищено по исходникам R007 | Что всё ещё требуется проверить |
|---|---|---|
| RimWorld 1.7 без DLC | Существующие `packageId`, DLL, `Scribe` ключи не меняются; новая функциональность опциональна и не касается ванильной генерации событий вне NJR | Настоящий `dotnet build`, игровая загрузка и рейды |
| Combat Extended | Без переписывания патронных комплектов/своих CE вербов; новая броня не снимает нативную экипировку | Боевая стрельба, снабжение, баллистика и GUI CE |
| Humanoid Alien Races / нестандартные тела | Проверка реальной `RaceProps.body` и совместимости слоёв; несовместимая броня пропускается | Полная совместимость семей/гендеров и рас, у которых другая модель одежды |
| Модовые фракции / PawnKind | Сохраняются оригинальные `PawnKind` и их оружие, список боевых зверей строится из `pawnGroupMakers` и кэшируется по фракции | FactionDef с динамически изменяемыми PawnGroupMaker/Def-ами |
| Ideology/Biotech/дополнения | Ни один из Scribe ключей, религиозных/пленнических событий и бизнес-правил не удалён | Сценарии с обращением, смешанными ксенотипами и без DLC |
| Старые сейвы R001–R006 | Только новые НЕсериализуемые runtime-кэши, `ExposeData` по-прежнему читает прежние ключи | Реальный Save/Load со множеством групповых выкупов |
| Большие колонии | Исключены линейные отрицательные поиски пленников и повторные проверки большой очереди прибытия | Реальные замеры TPS до/после, профилирование Unity |

## Отдельные нерешённые риски / не считать фиксами R007

- По игровым данным пользователя №01 и №16 всё ещё требуют полноценного повторного теста: спавн, маршрут мимо турелей, конвой, стройка, баррикады, вылет и отход.
- Настоящее использование `Verb_PowerBeam` для орбитального целеуказателя не тестировалось. Режим проверки выдачи вещей не подтверждает работу боевого Verb.
- В частности, некоторые HAR-расы не проходят нынешние критерии family generation (`gender != None`, off-map родители только ванильные Human); полноценный перенос на любую модовую расу НЕ заявлен.
- Без SDK и DLL игры недоступны C# компиляция, RimWorld runtime, CE/HAR и реальные TPS бенчмарки.
- Существующий код по-прежнему просматривает список Hostages один раз в 90–150 тыс. тиков и активные дела возмездия один раз в 30 тыс. тиков; это редкие контрольные проходы, а не горячий цикл, удалять их опасно.
- Если внешний мод напрямую редактирует публичный `Hostages` без вызова `InvalidateHostageIndex()` и при этом сохраняет прежнюю длину списка, сторонняя мутация может обойти кэш. Класс NJR сам учитывает все свои удаления; такая внешняя модификация не является документированным API NJR.

## Дополнительные игровое испытания после доступа к ПК

1. R006→R007: загрузить сохранение с несколькими пленниками и незавершённым групповым выкупом; отпустить одного, сохранить, загрузить, отпустить остальных, проверить оплату ровно один раз.
2. Модовая фракция в CE/VE/HAR: появление рейда с новым экипировочным пресетом; проверить, что броня/пояса из других модов не пропадают, а у стрелков не исчезают патроны.
3. Включить крупные волны прибытия (до 192), проверить родственников и политику без роста времени фонового тика; сравнить TPS на сопоставимых сохранениях.
4. При большом числе игровых пленников вызвать обычную команду выхода/освобождения и проверить отсутствие исключений Harmony и сохранение контрактов.
