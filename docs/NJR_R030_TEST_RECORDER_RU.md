# R030 — NJR Test Recorder (только разработка)

Основание: R029, запрос пользователя на отдельный диагностический модуль. R030 не изменяет поведение спасения/рейдов, спавн, баланс, маршрутизатор или боевые алгоритмы. Патч накопительный относительно R027 (включает R028/R029). Не считать работоспособность R029 подтверждённой.

## Тест в RimWorld
1. Установить новый ZIP из успешного GitHub Actions, запустить игру и включить режим разработчика.
2. На тестовой карте открыть меню Debug actions → `NJR - ЗАПИСЬ ТЕСТОВ` → `01 — Начать запись`. Это надо сделать **до** вызова рейда. В статусе должны быть события, успешные хуки и путь каталога. Необязательные несовместимые хуки отдельно отмечаются в логе, а не скрываются.
3. Закрыть окно статуса. Вызвать нужный сценарий (например 01 или 16). Желательно проверять по одному рейду, отдельно несколько одновременно. Если зависли, `02 — Метка и полный снимок карты`, затем дать игре немного времени, чтобы увидеть повторяемость. Метки не меняют игровой процесс. `03` — статус, `05` — последние ключевые записи.
4. `04 — Остановить и создать ZIP`. В окне указан полный путь. ZIP прикрепить к сообщению. Если игра аварийно завершилась или ZIP не создался, прикрепить каталог с `events-*.jsonl` (или самостоятельно упаковать его). Обычный Player.log тоже полезен, особенно для ошибок до начала записи.

Каталог: `GenFilePaths.SaveDataFolderPath/NJR_TestDiagnostics/<UTC-дата_время_GUID>/`. На Windows обычно под `C:\Users\<пользователь>\AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios\NJR_TestDiagnostics`. Использовать фактический путь из окна. ZIP лежит рядом с каталогом. Ничего автоматически не отправляется.

## Что записывается
- Вызовы Verse.Log Message/Warning/Error и Once-вариантов, включая другие моды и stack trace для ошибок. Это не перехват абсолютно всех внутренних систем движка или системного stdout. Вложенные вызовы логгера могут дать дубликаты.
- Реальные StartJob/EndCurrentJob и состояние после вызова, входные параметры, job-def, цели A/B/C, тип источника задания; отдельные JobDriver завершения. Все пешки карты, не только NJR.
- Доступные события pather: StartPath, PatherFailed, PatherArrived, координаты и (если поле/свойство доступно) узлы нативного пути; отдельно полный стратегический маршрут NJR, стоимость, стены/двери, опасность, расширения, pending, первая преграда, причина решения.
- Изменения тактической роли, назначенная клетка и объект, вызовы планировщиков и предлагаемые ими задания (включая null), фактическое состояние операции после решений, выбор места появления и выхода. Уникальный ID операции на сессию.
- Снимки всех пешек каждые 120 игровых тиков: позиция, ID, фракция, здоровье, статус пленника, Lord, duty, job, оружие. Операции: фаза, отряды, VIP, освобождённые, пары эскорта, выход, статус и объекты капсул, инженер, баррикады, бюджет, роли.
- Снимки карты при начале и метке: размеры, terrain/roof/standability по координатам (RLE), здания/предметы/чертежи/строительные рамы. Дельты объектов каждые 600 тиков; выбранные события появления, удаления, урона, смены фракции, выхода, Lord, крыш и рельефа; доступные события начала атаки. Уничтоженные объекты можно связать по ID. Покрытие хуков зависит от API RimWorld/Harmony и отражается в `session_start.hooks`.
- Время UTC, номер игрового тика, монотонное время от старта, порядковый номер, ID потока. При загрузке старого сохранения тик может уменьшаться, порядок событий сохраняется по seq.

## Ограничения
Запись выключена по умолчанию; перехваты устанавливаются при первом запуске и остаются инертны после остановки. Диагностика сама создаёт нагрузку: сериализация JSON, обход карты, запись на диск; `sample_cost` измеряет время снимков, не всю стоимость хуков. Для оценки TPS сравнить с выключенной записью. Не обещается запись каждого внутреннего микрособытия игры/CE. Все ошибки регистратора изолированы от игровых решений; первые 20 отражаются отдельным событием, счётчик есть в статусе. Отсутствующие/неустановленные хуки видны в заголовке, а не считаются успешно подключёнными.

JSONL-файлы разбиваются по 32 МиБ, без перезаписи старых сегментов. Суммарный предел 512 МиБ на сессию: запись явно остановится, `session-end.json` содержит причину. Ошибки консоли и метки сбрасывают буфер сразу; при продолжающихся событиях/снимках остальные — примерно раз в секунду. При аварийном выходе последняя порция может потеряться. Сессии хранятся отдельно; старые ZIP можно удалять вручную.

## Анализ и удаление перед релизом
`python tools/njr_diagnostics_read.py <zip>` — сводка, включая ошибки, маршруты, всплески StartJob и последние состояния операций. `--kind route`, `--pawn ID`, `--operation ID` — фильтры. Только чтение, без распаковки и сторонних пакетов.

Весь модуль в `Source/Diagnostics/`. Единственный вызов из штатного кода обёрнут в `#if NJR_TEST_DIAGNOSTICS`. В csproj тестовая сборка включена по умолчанию; перед релизом `dotnet build RaidersHaveFamilies/Source/RaidersHaveFamilies.csproj -c Release -p:NJRDiagnostics=false` исключает файл и вызов. Удалить папку Diagnostics, флаг и тестовый CI-шаг/документацию при финальной чистке. Никаких новых сохраняемых MapComponent, Def, Scribe-полей или RNG игры.

Локальная проверка исходников не доказывает компиляцию DLL или установку всех runtime-хуков; проверить успешный GitHub Actions и заголовок первой реальной сессии. Сохранить логи №01 и №16 отдельно.
