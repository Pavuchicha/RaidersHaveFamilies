**Дата среза:** 23.11.2026. **Статус:** исходники v0.14.0-beta2 + два локальных P0-пакета 22.11 + экспериментальные доработки R001. **Не объявлять релизом:** новая серия не компилировалась настоящими RimWorld/.NET DLL и не тестировалась в игре. Полный исходный RAR пользователя распакован, архив `.git` сознательно исключён. Пользователь сейчас без доступа к ПК.

## 0. Главная инструкция для следующего разработчика

1. Работаем **только над NJR (Not Just Raiders)** — бывший *Raiders Have Families*. Заброшенный *ThornCorps* — отдельный проект, НЕ смешивать оружие/CE баланс из него с NJR.
2. **После КАЖДОГО содержательного ответа** выдавать обновлённый **единый полный ZIP архива разработки** (исходники + все ТЗ + кодовые решения + история + жалобы + текущий статус + задания Агенту А + тесты и результаты). Не терять ничего из архива предыдущей итерации. Архив должен быть удобен для передачи другой итерации без необходимости вспоминать разговор.
3. Пользователь обновляет проект обычной **заменой файлов в корневой папке GitHub Desktop**: `Repository → Show in Explorer → распаковать исходный overlay с заменой → Commit to main → Push origin → зелёный GitHub Actions → установить свежий собранный мод`. **Не батник, не git apply, не ручное редактирование отдельных файлов.** Передавать готовый ZIP с полными файлами и строку `Summary` при просьбе; **каждый ответ в конце должен содержать конкретные действия пользователя**. Пока пользователь без ПК — действий от него не требуется.
4. **Агент А** — независимый исполнитель и рецензент. Ему можно поручать анализ, C#, тесты, алгоритмы, расследование первопричин, документацию и CI, **кроме чтения или записи ZIP/RAR**. Работает с отдельными файлами/репозиторием. Нельзя заявлять, что работа А выполнена, если агент реально не запускался и не представил отчёт.
5. ТЗ читается СЛОЯМИ: `IMPLEMENTATION_SPEC_RU.md` (развёрнутое исходное), `REQUIREMENTS_AUDIT_MASTER_RU.md` (идентификаторы A01–F09, 82+ пунктов), `TACTICAL_DOCTRINE_DESIGN_RU.md` (рейдовые доктрины), далее документы `docs/NJR_*` и история `RHF_*`. **Ни одно исправление частного примера не отменяет требований ко всем аналогичным операциям.** Не переписывать исходное ТЗ на основе домыслов: добавлять новые дельты отдельно.
6. Метрики: `KОД` = код существует, `STATIC PASS` = Python-контракты прошли, `BUILD PASS` = реальный CI компилировал новую DLL, `GAME PASS` = пользователь/доступная игра реально проверили. Эти метки никогда не взаимозаменяемы.

## 1. Продукт / совместимость

- Название интерфейса: **NJR — Not Just Raiders** (не *Raiders Have Families*).
- RimWorld: **1.7**, Harmony 3, `.NET 10`, ссылка на `Krafs.Rimworld.Ref 1.7.5014-unstable`.
- `packageId = pavuk.raidshavefamilies` **не переименовывать**; C# `namespace RaidersHaveFamilies`, `RaidersHaveFamilies.dll`, сохранённые `RHF_*` DefName, Scribe-ключи — **не переименовывать** ради бренда.
- Исходники в GitHub по-прежнему лежат в `RaidersHaveFamilies/`; папка **установочного** мода новой сборки — `NJR-NotJustRaiders`. В `Mods` должен стоять один экземпляр, старую папку `RaidersHaveFamilies` удаляют после получения нового бинарного архива. На скриншоте 22.11 у пользователя была старая папка и старое отображаемое имя — **не путать ситуацию старой установленной DLL с доказательством ошибки новых исходников**.
- Публичный репозиторий `Pavuchicha/RaidersHaveFamilies`, ветка `main`. Прямая запись из интеграции GitHub ранее вернула 403; нельзя заявлять, что код автоматически запушен.
- Ярлык workflow/артефакта пока остаётся `v0.14.0-beta2`, потому что множество унаследованных Python-контрактов жёстко проверяют его; **это не отражение стадии разработок R001**. При стабилизации переименовать все соответствующие тесты и workflow атомарно.

## 2. Полное игровое ТЗ — области

### A: семьи, отношения и жизненный цикл

- Не только рейдеры: торговцы, гости, караваны, экспедиции, военные, модовые гуманойды (если совместима биология/RelationDef).
- Реальные связи на вкладке «Социум» без dev-флагов: родители, дети, родные/полуродные братья/сёстры, старшие поколения, дяди/тёти, племянники, кузены; супруги, любовники, бывшие, женихи/невесты, усыновлённые и сводные — **не подменять кровное родство фальшивым RelationDef**. Внутри группы и во внешнем мире; учитывать ориентацию, полигамию и согласованные генеалогии.
- Переиспользовать **существующих** `WorldPawns` прежде генерации новых, не изменять чужие ванильные связи без основания. Ограниченные бюджеты на волну и сохранение; источники/provenance; бережная очистка только собственных невостребованных созданных пешек и связей.
- R001: добавлен ограниченный предвыборочный поиск существующих свободных WorldPawns одной фракции перед генерацией; только люди, биологически правдоподобные свободные родительские позиции. Это **частичный шаг**, а не завершение всех A01–A10; нужны тесты семей после 1/30/300 рейдов.

### B: ранг, должности и реальные полномочия

- Значимость 0–8, реальные лидеры/должности из `Faction`, `PawnKindDef`, Royalty и модовых факторов имеют приоритет. Нельзя текстово сделать случайного солдата настоящим королём. Значимость влияет на переговоры, угрозы, рейды, семье и цену; редкость случайного спавна VIP. UI в информации и пленнике; отдельные расшифровки «цена выкупа», «цена продажи», «goodwill».

### C: переговоры и пленники

- Только через настоящую Comms Console, фракционный `Dialog_Negotiation` и физическое действие переговорщика. Деревья ответа фракции/семьи должны различаться по реальным сведениям, характеру, предыдущим отказам, репутации; никаких метазнаний.
- Выкуп серебром; вероятность дополнительных требований отдельно в %; влияние здоровья, ранга, истории издевательств, отказов, навыка, отношений. Цена не выплачивается до безопасного **физического выхода** пленника. Выплата реальными капсулами и письмо с местом доставки. Бесплатный выпуск даёт goodwill или внутреннюю политическую репутацию у permanentEnemy.
- Признания, медицинские отчёты и распространение сведений раздельны; раскрытие факта не равно признанию умысла. Важные завербованные пленники могут вызвать месть. Обращение в другую Ideology можно сообщить только после фактического обращения; сторонники новой идеи получают положительное воспоминание, прежней — отрицательное; эффект ограничен и не дублируется бесконечно.
- **Не реализовано полностью:** вооружённая делегация для VIP с физическим сопровождением и расчётом, многостадийные политические переговоры, групповая сделка с дальними колониями, полноценный агент эмоций дипломатов.
- **R001:** групповой выкуп 2–12 ещё удерживаемых одной фракцией на одной карте: единая сумма/договор, подтверждение каждого выхода, одна фактическая доставка только после полного освобождения, отказ при гибели/вербовке/продаже. Состояние сериализовано. Статус — **статический прототип, без игрового PASS**.

### D: медицина, Ideology, ответственность, мораль

- Журнал подтверждённых операций, частей тела и врача; военные ранения до плена не считать пытками, болезнь не считать жестокостью; встроенный WCE2 при наличии подтверждённых recipe/precepts, без подмены чужих DLL. Качественные протезы снижают претензии/дают компенсации. Разделка трупа и непосредственное поедание требуют реального события.
- Сообщение по связи о подтверждённых зверствах влияет на goodwill, реакции семьи и соответствующие черты/принципы, **не все колонисты получают бонус**, не выдавать его при тайном поступке. Стадии эмоций ограничены. Религиозный доклад: точные Ideo, воспоминания позитивные/негативные по реальной принадлежности. R001: реакция фракции на скрытое обращение отложена до публичного доклада, не больше внезапного «экстрасенсорного» знания.

### E: все 18 событий и общая тактика

- Разделённые фазы рейда: причина/цель/состав/способ прибытия/план проникновения/сражение/извлечение/отход или последующая месть. Значимые роли: штурм, прикрытие, отвлечение, сапёры, охрана, санитарная эвакуация, конвоир, инженер. Снаряжение из реального бюджета/TechLevel и ограничений фракции; уважать CE, модовые расы, боеприпасы.
- 01 обычное наземное освобождение; 02 несколько пленников; 03 VIP; 04 полевая капсула; 05 наёмники; 06 фракционная коалиция; 07 прямой карательный штурм; 08 племя + боевые звери; 09 высокотехнологичный десант; 10 осада; 11 спасение + отвлечение; 12 3+ фракций; 13 наёмники + отвлечение; 14 пролом + штурм; 15 десант + отвлечение; 16 VIP + баррикады + полевая капсула; 17 спасение → карательный штурм; 18 охота на завербованного VIP.
- Сложные рейды должны реально взаимодействовать с картой, щадить несущественную мебель и приоритетно пользоваться дверями, обходить опасные башни, выбирать доступное место появления, поддерживать единый маршрут эскорта, отступать после спасения; не телепортировать пленников, не рисовать фиктивную капсулу, не разрушать объекты ради простоты планировщика.
- VIP-десант: если физически безопасно — в камеру/непосредственно рядом; занять помещения, перекрыть **реальные двери между комнатами** физическими стальными баррикадами без блокирования своего последнего выхода, построить два настоящих элемента через blueprint/frame/workgiver, принести из инвентаря реальные материалы, посадить в CompTransporter, запустить настоящее путешествие. При отсутствии условий — честный fallback по альтернативному маршруту, а не вечное ожидание или фальшивый успех.
- Нет глобальной подмены `HostileTo` у всех фракций: возможные временные коалиции ограничены только участниками операции. Технологичные враги обладают подходящей огневой мощью, племена — числом и зверями, но без бесплатной техники/снаряжения. До 5 parties и бюджет ограничен.
- Квесты освобождения пленников в чужом поселении/лагере (диалог «иди за мной», реальный вывод и награда), VIP-делегации и орбитальные средства всё ещё НЕ реализованы полностью.
- **Критические игровые провалы 22.11:** 01 появляется за непроходимыми горами, идёт на турели, после освобождения бегает туда-обратно; 16 бессмысленное разрушение мебели/стены вместо двери, капсула иногда не строится, после пусковой стоят, одна бессмысленная баррикада. Подробности: `docs/NJR_OPEN_DEFECTS_AND_TEST_MATRIX_R001_RU.md`. Предыдущие P0 локальные исходники наложены, **но пользователь их ещё не проверил после последнего ZIP**.

### F: QA/TPS, сборка и передача

- Совместимость RimWorld 1.7 без DLC и с Ideology/Royalty/Biotech/Odyssey; CE, WCE2, HostageTaker/Prisoner Exchange, крупные моды, PerformanceFish/RocketMan. **Ни один из этих наборов не может быть заявлен GAME PASS без проверки.** Не проверять каждую пешку каждый тик. Сканировать ограниченные группы только по событиям/редко. Сохранять/загружать на всех фазах.

## 3. Разработка по состоянию R001

**Исходники:** оригинальный RAR пользователя от 22.11 → overlay `NJR_S41_P0_GITHUB_DESKTOP_REPLACE.zip` → overlay `NJR_S41_P0_22NOV26_GITHUB_REPLACE.zip` → экспериментальные изменения R001. Ветки на GitHub автоматически не менялись.

**Код R001:**
1. `RaidersHaveFamilies/Source/RaidersHaveFamilies.cs`: `ReuseIndependentWorldKin` — переиспользование существующих свободных world pawn по ограниченному перебору (макс. 256 проверки после макс. 255 пропусков на группу, не в каждом игровом тике), общее происхождение, ограничение степени родства. Ledger получил сериализованный `NextGroupRansomId`.
2. `RaidersHaveFamilies/Source/NJRGroupRansomV15.cs`: единая сделка на группу, сумма, фиксация имён и количества, физическая выплата единой партией, отмена при нарушении условий. `RHFHostageSystems.cs`: новые Scribe поля, обработчики смерти, выхода, вербовки; Ideology раскрытие; `RHFDialogue.cs`: меню групповых переговоров.
3. `.github/workflows/build.yml` и три новых Python-гейта 206/207/208. Пакет сохраняет старые serial key-и. **DLL не компилировалась локально**, игровой тест невозможен без ПК.

**Открытые риски R001:**
- `WorldPawns.AllPawnsAlive` в разных сборках возвращает `IEnumerable<Pawn>`; код использует foreach, без .ToList. Не доказано, что выбранные world pawn не захвачены модовыми специальными историями; требуется реальная проверка на разных модах.
- Групповой выкуп: при исключении `DropPodUtility.DropThingsNear` отказ фиксируется, выплата не засчитывается; автоматическая повторная доставка не реализована во избежание потенциального дублирования при частично успешном спавне. Нужна отдельная безопасная retry-модель.
- Претензии по 01/16 остаются P0 до нового живого теста. Нельзя считать их закрытыми только потому, что имеются изменения с пометкой P0.

## 5. Неотменяемые правила

- Сначала доказываем первопричину; не маскировать лог `try/catch`, не отключать ошибочную механику вместо исправления, не выдавать Python-тест за игру.
- Изменения должны улучшать **все аналогичные сценарии**, а не подкручивать только конкретный номер dev-команды.
- Нельзя ломать текущее сохранение ради смены бренда; при добавлении новых полей использовать уникальные `Scribe`-ключи и дефолт старых сейвов.
- По возможности отдавать агенту А конкретные независимые задачи и требовать доказуемый вердикт без ZIP. Пользователь не обязан заниматься CI, пока у него нет доступа к ПК.
- В конце ответа — предельно простая инструкция **«Что тебе сейчас делать»**, без вопросов о уже известных фактах.
