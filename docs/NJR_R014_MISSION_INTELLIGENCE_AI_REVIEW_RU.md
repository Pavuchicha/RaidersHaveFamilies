# NJR R014 — ревизия разведданных, непредвиденных перемен и боевых ролей

Дата: 2026-11-23. База: R013. **SOURCE-ONLY**, без DLL/RimWorld PASS.

## Принцип

Искусственное снижение сложности ИИ ради TPS не допускается; неизменённые пассивные проверки не ускорены и не усложнены. Изменения применяются только к собственной миссионной системе NJR, не к всем пешкам RimWorld. Ванильные Lord осад и животных не заменяются. Нельзя превращать разведданные союзника в метазнание о непрерывном движении невидимой пешки. При этом замеченную стационарную турель фракция не обязана забывать после закрытия двери.

## Выявленные дефекты и изменения кода

### 1. P0 — живые невидимые цели в приказах не наблюдавших их бойцов

**Файл:** `RaidersHaveFamilies/Source/RHFOffenseS41.cs`.

**Причина:** `PlanFaction` передавал `objective == op.HuntTarget` всем бойцам как `order.Objective`, даже если **только один** разведчик мог видеть перебежчика. При следующих заданиях `OffenseStrike`/`OffenseCover` цель оставалась прямой ссылкой на подвижную пешку; обращение к её `Position` выдавало новые координаты через стены. Отдельная защита существовала только у `OffenseHunt`.

**Исправление:** `IndividuallyConfirmed` передаёт ссылку на пешку только наблюдателю с реальной линией видимости; остальные получают зафиксированное при составлении приказа положение. `RHFOffenseRoleJobGiverS41` повторно проверяет видимость любой пешки-цели (не только дефектора); `contactGoal` не берётся из незримой актуальной позиции. Разведчик всё ещё может сообщить **последнее известное положение**, но не непрерывный трекинг. Проверка `Seen` больше не обрезает наблюдение искусственными 60 клетками; ограничительом остаётся физическая `GenSight.LineOfSight`.

### 2. P1 — потеря разведданных о турелях за закрывшейся дверью

**Файлы:** `RHFTacticalBoardS41.cs`, `RHFOffenseS41.cs`.

**Причина:** `KnownTurrets` рассчитывал только турели, которые прямо сейчас видны кому-то из отряда. После перемещения за стену или закрытия двери знакомая турель исчезала из оценок безопасного маршрута. Ранее просмотренная опасная комната могла считаться свободной.

**Исправление:** `RHFObservedTurretS46` содержит `FactionKey`, `Thing Turret`, `LastSeenTick`. Наблюдения добавляются только после `TeamSees`, а воспроизводятся **только крылом той же фракции**. Данные сохраняются с `Scribe_Collections.Look(...LookMode.Deep)`, старые сохранения получают пустой список после загрузки. Ссылка удаляется при уничтожении, исчезновении, смене владельца, перемещении на другую карту. `NJR` не узнаёт координаты ещё ни разу не замеченной турели; для разных фракций коалиции нет бесплатного обмена знанием. Прямого доступа к чужому AI-моду и глобальной замены Pathfinder нет.

### 3. P1 — устаревшая цель могла оставлять весь отряд ждать

**Файл:** `RHFOffenseS41.cs`.

**Причина:** стандартный `ReplanTicks=270`; когда турель или стена исчезала, задание на её уничтожение могло продолжать существовать до следующего срока без реальной работы. Аналогичный сбой после открытия двери или смены принадлежности цели.

**Исправление:** `HasInvalidActiveOrders` проверяет существующие приказы на штатном тике операции, немедленно инициирует перепланирование при исчезновении/уничтожении цели, открытии запланированной двери-преграды либо переходе цели из фракции игрока. `JobGiver` дополнительно отбрасывает текущую **не-вражескую** цель в том же job-поиске. Нет искусственного ускорения всех проверок до каждого тика игры.

### 4. P1 — боец, неспособный к насилию, мог назначаться проломщиком

**Файлы:** `RHFCombatPlannerV125.cs`, `RHFOffenseS41.cs`, `NJRCombatContactS44.cs`.

**Причина:** отбора по `Manipulation`, оружию и достижимости было недостаточно для пешек с disabled `WorkTags.Violent` (включая сторонние расы/истории). Такие пешки получали невыполнимые боевые задания. **Исправление:** явная проверка `WorkTagIsDisabled(WorkTags.Violent)` до назначения атакующего проломщика и при формировании контактной атаки. Мирные снабженцы при этом не телепортируются и не лишаются иных задач.

## Исполненные проверки

- Проведено ручное сравнение вызывающих методов `Tick → PlanWing/PlanFaction → RHFTacticalBoard → RHFOffenseRoleJobGiver → NJRCombatContact`, плюс сериализации `ExposeData` и активного `Prune`.
- 75/75 отдельно запускаемых существующих и новых Python source/reference-model tests прошли (см. `docs/NJR_R014_TEST_RESULTS.json`); два унаследованных теста обновлены с запрещённых теперь старых предположений.
- Лексическая балансировка фигурных, квадратных, круглых скобок для четырёх изменённых C# файлов; это **не C# компиляция**.
- Новый `tests/njr_220_mission_intelligence_r014.py` включён в `.github/workflows/build.yml`.

## Что осталось не доказано

1. **Нет .NET SDK/игрового рантайма в среде работы**: проект не компилировался в этой итерации; реальные C# ошибки или конфликт с RimWorld API всё ещё возможны. Цель — обязательный зелёный GitHub Actions.
2. Не подтверждена корректность всех 18 сценариев в игре и особенно реальные №1 и №16. При настоящем тесте проверить: увиденную турель за потом закрывшейся дверью; потерю обзора перебежчика; уничтоженную в ходе движения цель; выход инженера; переставшую быть вражеской пешку; save/load в середине боя.
3. **Нет гарантии следования vanilla `Goto` по рассчитанному safe-first коридору клетка в клетку**. Это отдельная открытая проблема маршрутизации, особенно с динамическими дверями и Combat Extended.
4. Невозможно гарантирoвать отсутствие всех зависаний на любой модовой карте без воспроизведения, инструментального логирования JobDriver/Lord и тестов реальных построек.
5. Одиночный выкуп с неопределённым результатом создания капсул всё ещё имеет открытый риск выплаты и не входит в R014.

## Следующие задачи

- Реальная тактическая координация двух независимых проломных крыльев с учётом физической возможности совместной атаки (не запрещать нескольким сапёрам разрушать один толстый участок, если это тактически выгодно).
- Проверить успешность **фактического пути JobDriver** против найденного safe-first маршрута; отклонение от коридора должно запускать переоценку, а не бесконечное `Goto`.
- Повторная выборка цели при исчезновении стрелка/инженера и проверка безопасности blast-зон для CE.
- Измерять и улучшать пассивную производительность отдельно от боевых ограничений.
