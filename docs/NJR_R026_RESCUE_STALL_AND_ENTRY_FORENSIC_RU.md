# NJR R026 — срыв спасения №1: простои у стены и повторяющийся край карты

## Основа
R025 (скачанный архив разработки и проверенный коммит `6d7904ad6b538c1286c8a6e911fecb4a7cb1a27a`).
Сценарий пользователя: в тесте №1 штурмовая группа оказывается у западной стены камеры, не освобождает пленника и остаётся неподвижной; высадка многократно повторяется на одной стороне карты.

## Исходные причины, подтверждённые кодом

1. `RHFRescuePlannerS41.Infiltrate`: даже при доступном через ванильную `CanReach` пленнике продолжал использовать план A*, в котором могла оставаться цель пролома. При `route.Valid`, но без пригодного waypoint, выдавал `Hold`; обход для доступного пленника работал лишь при `!route.Valid`.
2. `RHFCombatPlannerV125.SelectBreachOperator`: бойцов с ракетным/гранатным/иным неразрешённым для безопасной стрельбы оружием исключали **полностью**, хотя безопасная ближняя атака двери/стены возможна. Если другой взломщик не мог дойти, возникал тупик.
3. Маршрутизатор сохранял неподъёмную стену как `FirstBarrier`; без назначенного исполнителя её не исключали из последующего поиска. Единственный запрет на отдельный пролом мог привести к переключению A/B.
4. `RHFRescueGroundEntryS41.Choose`: `valid` набирал до 8 ближайших точек на стороне с расстоянием в одну-две клетки, затем короткий список `max(5000, score/3)` фактически возвращал только ближайший сектор. В отладочных прогонах с повторно загруженным RNG даже случайный выбор воспроизводил прежний результат.
5. В диагностике V124 выводились устаревшие сведения о командовании, но не ключевые поля реально действующего S41-планировщика: `Barrier`, `Breacher`, `Decision`, `RHFOrderS41`.

## Поправки

- При подтверждённой `CanReach` к пленнику прямое движение к цели имеет приоритет; прежние структурные атаки отменяются. Такой переход выполняется на обычном тактическом пульсе (не глобальном тике пешки).
- Любой физически способный атаковать боец может выполнить `AttackMelee` по **разрешённой структуре**, в том числе если его основное оружие — взрывчатка. Реального взрыва или синтетического урона мод не создаёт.
- Если никто не может достичь разрешённого препятствия, оно на 1800 тиков исключается из альтернативного A*. Список исключений ограничен восемью препятствиями, предотвращая возврат к предыдущей стене.
- Безопасные точки появления отбираются пространственно разделёнными секторами вдоль сторон карты (не менее 15 клеток между центрами одной стороны). Сначала выбирается допустимая сторона, затем площадка. В принудительных **debug**-рейдах генератор не воспроизводится при перезагрузке того же сохранения. Для обычных рейдов используется штатный RimWorld Rand. Остаётся строгий запрет воды, пещер, тумана, горных крыш и недостижимых кластеров.
- Диагностика на карте: `NJR - ТЕСТЫ | ДИАГНОСТИКА` → `29 — Диагностика спасения S41 и эвакуации`. Включает роль, цель, последнее решение S41, препятствие и исполнителя, текущий Job и Lord. При простое более 1200 тиков выдаётся однократный `[NJR][R026][STALL]` в `Player.log`.
- Маркер запуска DLL `[NJR][R026] Route/mission authority loaded` — должен присутствовать в `Player.log` **новой** сборки.

## Верификация

- 85/85 статических/модельных проверок CI пройдены тремя группами. В том числе исправлены проверки старых точных строк (`njr_211`, `njr_216`, `njr_227`, `njr_229`, `rhf_124`) без удаления их смысловых требований.
- `tests/njr_230_r026_real_rescue_anti_stall.py`: источник-приоритет `CanReach`, преодоление блокировки взломщика, ограниченный поиск без недоступного препятствия, разброс по сторонам, маркеры логов.
- C# DLL не собрана локально: `dotnet` не установлен в доступной среде. Локальный Python не заменяет компиляцию RimWorld 1.7 / Harmony 3.
- Игрового теста у пользователя не было. **Нельзя объявлять спасение №1 исправленным по этим результатам.**
- Спасение №16 и строительство пусковых установок не менялись.

## Приёмка по фактической игре

1. После загрузки новой версии проверьте `Player.log` на `[NJR][R026]`. Если строка отсутствует — активная DLL не этой ревизии либо загрузка сорвалась; проверить дубликаты модов и первую ошибку загрузки.
2. Отладочное спасение №1 на прежней карте: наблюдать первое продвижение, атаки только по утверждённой двери/стене, освобождение пленника, выход конвоя. Маршрут через открытую дверь не должен заменяться новым проломом. Никаких ударов по генераторам.
3. При остановке открыть Debug Action 29, сохранить текст диагностического окна и `Player.log` с `[NJR][R026][STALL]`. Они покажут отказ исполнения после построения плана, если он остаётся.
4. Запустить спасение №1 несколько раз: если площадок реально несколько, должна отличаться сторона/район высадки. Одно место допустимо только когда остальные кандидаты отклонены физическими проверками; строка `[NJR][R026][GroundEntry]` сообщает `valid`, `eligible`, `side`.

R025 оставлен как обратимая контрольная ревизия. Не смешивать два ZIP модов внутри `Mods`.
