# NJR v0.14.0-beta2 — интеграционный отчёт по игровым замечаниям

Основа: опубликованная ветка main `cf4248d2ffde6f3f7cac61378f986e2e31e1b8e5` (v0.14.0-beta1). Все исходники, DefNames, namespace и packageId сохранены для совместимости.

## Обновления

1. Наземные спасатели (№1). Участок массовой высадки проверяется на свободную от горной породы площадку вокруг центральной клетки; запасной ванильный алгоритм сохраняется для карт без безопасного подхода. Планировщик при кольце турелей не ограничивается поиском немедленной линии огня: ищет ограниченные достижимые позиции для физического сближения и стреляет только при корректной линии огня.
2. Десант (№16). Приоритет: безопасное помещение пленника, соседняя комната с дверью к камере, прочая внутренняя комната, затем улица. Проверяются крыша, опасность для пленника, турели и достаточное пространство для группы. Оригинальная механика DropThingGroupsNear распределяет капсулы вокруг центра, поэтому полная безопасность всей высадки **не доказана**.
3. Пусковая (№16). Выбор площадки аналогично предпочитает камеру/соседние помещения. Допустима физическая разборка не более двух подходящих обычных стен; удаление происходит штатными ударами боевого инженера, без мгновенного удаления. Несущие стены с толстой крышей не разбираются. Для пусковой под тонкой крышей добавлена работа по её удалению за время до настоящего запуска.
4. VIP. Освобождённый пленник, не состоящий в командном `Lord` спасателей, получает собственное задание посадки в настоящую капсулу; подтверждение успеха только после фактического нахождения в контейнере.
5. Бюджеты. Базовые очки угрозы берутся из ванильного расчёта; значения важности пленника, числа пленников той же фракции и политического давления (-100..0) меняют силу. Дополнительных жёстких пределов 300–15 000 очков нет. Каждая фракция коалиции или отдельные наёмники получают самостоятельную полную стоимость отряда, а не долю одного общего бюджета.
6. Имя. Отображаемые заголовки и описание продолжают переход с RHF на NJR. `RaidersHaveFamilies` остаётся именем **внутренней папки и сборки** — это намеренно во избежание проблем загрузки старых сохранений.

## Качество проверки

59 статических Python-сценариев и аудитов CI: PASS. XML/структуру проекта проверяет `njr_200_integrity_audit.py`. Проверки **не являются** компиляцией C# или игровыми тестами. Реальная сборка под RimWorld 1.7 должна выполняться GitHub Actions после публикации; после неё отдельно воспроизвести все 18 вариантов в игре, особенно №1 и №16.

## Остаточные риски

- Центр десанта оптимизируется, но ванильный разброс отдельных капсул может выбрать иную клетку.
- Невозможно обещать прорыв абсолютно любой окружённой турелями базы: остаются реальные ограничения оружия, обзора и маршрута.
- Физическая разборка стен/крыши и завершение строительства требуют игрового подтверждения на разных типах помещений и крыш.
- Конфликтующие моды CE, архитектура NPC и сохранения после длительной игры требуют отдельного тестирования.
