# v0.12.1 — тактическая целостность и исправление эвакуации (дополнение к v0.12.0)

**Главный исправленный дефект:** после реального запуска VIP-капсулы `FlyShipLeaving` держит пленника в транспортном контейнере, привязанном к карте. Предыдущий код воспринимал `MapHeld == map` как доказательство, что VIP не эвакуирован, и не переходил к следующей фазе. Теперь `PodLaunchCompleted` исключает этого VIP из наземной очереди; остальные заложники по-прежнему требуют вывода по земле.

**Многопленные операции:** освобождённые раньше остальных теперь не получают свободу самостоятельно бежать и теряться, пока группа штурмует следующие камеры. Ограниченное число приказов удерживает их рядом с назначенным сопровождающим. После освобождения последнего они выходят совместно.

**Охота на вербованного VIP:** сохраняются последняя увиденная клетка и время контакта; корректная цель появляется лишь после фактического визуального обнаружения одним из максимум 16 участников группы. Сквозь стены и туман поиск не ведётся. До первого контакта группа прочёсывает поселение, не получает сверхъестественных координат. При утере контакта последняя точка устаревает.

**Огневое прикрытие:** приказ на обстрел ограничен реальной линией видимости, что устраняет бессмысленные выстрелы через стену камеры.

**Ограничения:** это групповой контроллер и штатный AI RimWorld, не полноценный новый LordJob. Изменения проверены *только структурно*; GitHub Actions и RimWorld должны подтвердить DLL и настоящую игру. Проблемы автосемей, WCE2, коалиций исторически враждующих фракций и CE остаются открытыми до живых тестов. Автоматический выпуск новых версий невозможен без действия пользователя в GitHub Desktop.

# Raiders Have Families — передача v0.10.1

**Полный накопительный ZIP**: включает v0.7.0–v0.10.0 и исправление v0.10.1. В частности, релиз v0.10.0 действительно получил зелёную компиляцию GitHub Actions #44922002687, но новый v0.10.1 пока не компилировался.

## Главное исправление (P0)
Раньше `RHFPreceptNotes` **только** дописывал текст в `PreceptDef.description`. Поэтому подсказка принципа показывала длинное пояснение, но пункт в штатном разделе «Настроение» не появлялся. Это не соответствовало запросу пользователя.

Теперь инъецируется `RHFPreceptMoodEntry : PreceptComp_SelfTookMemoryThought` в `PreceptDef.comps`: именно этот тип RimWorld обрабатывает в секции `Mood` метода `Precept.GetTip`. В нём указаны настоящие RHF ThoughtDef (5 дней), он пишет лаконичные строки в секции «Настроение», но его игровой обработчик истории **преднамеренно отключён**: воспоминание по-прежнему выдаётся отдельно **за новое публичное раскрытие** через `RHFMoralResponse`/`RHFMercy`. Ванильные/WCE2 эффекты не изменены. Применено для пыток, каннибализма и милосердия.

## Обновление
1. GitHub Desktop → Pull origin (если доступен) → Repository → Show in Explorer.
2. Скопировать **всё содержимое ZIP** в корень репозитория с заменой (`.github`, `RaidersHaveFamilies`, `tests`, документация).
3. Summary: `RHF v0.10.1 - Fix native Ideology mood entries`.
4. Commit to main → Push origin → дождаться успешной сборки Actions `Build Raiders Have Families 0.10.1`.
5. При успехе скачать `RaidersHaveFamilies-RimWorld-1.7-v0.10.1-IDEOLOGY-MOOD-TEST`, распаковать вложенный install-ZIP, установить папку `RaidersHaveFamilies` с DLL поверх старой версии **после удаления старой папки**. Сохранение заранее скопировать.

## Проверка
Открыть экран Ideology → принцип «Пытка: всегда приветствуется» → в самой секции **«Настроение»** должна появиться отдельная строка `RHF — Обнародованы мучения...: +2 / +4 / +8 / +16 / +32 / +48` ниже стандартных бонусов WCE2. Для «Милосердия» — две строки о гуманном освобождении/продаже; для подходящих принципов каннибализма — строка +48 за публичное признание. Обычный WCE2 бонус +5 за пытку остаётся на месте. Никакого RHF-воспоминания до события **не должно** появляться в «Потребности».

Для дополнительной проверки после загрузки карты команда разработчика №19 сообщает `строк RHF в разделе Настроение` для идеологии каждого свободного колониста. Показатель больше нуля подтверждает регистрацию компов в текущей идеологии, но не заменяет визуальную проверку.
