# Raiders Have Families — пакет передачи v0.6.0 (2026-11-21)

## Приоритет пользователя

Основная цель: высокий TPS, глубокие социальные связи, система рангов и отношения пленников с фракциями, правдоподобные диалоги о выкупе, последствия жестокости/органных операций/WCE2, фракционные операции спасения и мести. Строгая проверка делом, а не формальное наличие методов. Установка **только через GitHub Desktop**, GitHub Actions создаёт готовую DLL и ZIP. Подключение GitHub от ассистента читает репозиторий, но запись была заблокирована HTTP 403 — пользователь копирует ZIP в локальный репозиторий и Push.

## Репозиторий и состояние

- GitHub: `Pavuchicha/RaidersHaveFamilies`, main.
- На 21.11.2026 сборка v0.3.1 в GitHub была **зелёной** (Actions run 44905522785); v0.4.0 не имела подтверждённой сборки и, судя по тестовым скриншотам, не была установлена.
- Текущая поставка `v0.6.0` — **интегрированный исходный пакет** на базе v0.4.0, включающий исправления этого запроса. `dotnet` отсутствует в среде; **новая DLL не собрана** и игровая загрузка не проверена. Проверки Python/XML не равны компиляции.

## Жалобы игрока и принятые меры

1. В разговоре «обычный гражданин или рядовой» неестественно → `RHFRanks.cs` заменён список неточных составных статусов на ранговые понятия без «или».
2. Пешка не шла к консоли → удалён Harmony-патч `Building_CommsConsole.GetFloatMenuOptions`, который открывал меню в обход ИИ; теперь `FactionDialogMaker.FactionDialogFor` получает дополнительную ветку **только после штатного вызова фракции**. `RHFDialogue.cs` реализует дерево `DiaNode`.
3. Разговор должен быть с конкретной фракцией → ветка появляется только при наличии её пленника, без общего списка всех фракций.
4. Нет реальных диалогов → ответ зависит от тяжести здоровья, ранга, известного родственника и известных операций; есть отдельные ветки подтверждения жизни, условий, сообщения о здоровье и отказа. Не выдавать за систему полноценного языкового ИИ: это шаблонные диалоги, но динамичные и контекстные.
5. Число серебра показывалось до переговоров и `+35%` непонятно → список пленников без цены, цены только в разделе условий. `+35%/+80%` заменены на конечные суммы серебра и **отдельные** проценты оценки вероятности согласия.
6. Фраза «родные просят подтвердить, что жив» без опции → теперь есть реальное отдельное действие подтверждения жизни без выкупа.
7. Условия выплаты засоряли вступительное окно → малое `Messages.Message` только после принятия условий.
8. Нет указателя на получение серебра → в `OnPrisonerExit` пробуется место выхода, `Messages.Message(..., LookTargets, ...)` кликабельно ведёт на выданное серебро.
9. «Сообщить о травмах» было в «условиях выкупа» → в `RHFDialogue` отдельная ветка медицинского отчёта.
10. Вырезанный орган, WCE2 ухо не давали последствий → `RHFWarCrimesIntegration` расширен: на старте Harmony-патчит найденные `RecipeWorker.ApplyOnPawn` для вредоносных WCE2 операций и распознаваемых ванильных операций органов. Факт записывается в `RHFHostageRecord` с описанием/тяжестью; после раскрытия `RHFHostageDiplomacy.ReportCondition` показывает точную проверку goodwill/внутреннего отношения и количество получивших воспоминание RHF. **Обязательно проверять число зарегистрированных хуков командой 14**. Не гарантировать точную обработку всех сторонних операций без лога/теста.
11. «Репутация не падает» у -100 перманентных врагов → невозможно опустить goodwill ниже -100, а у `permanentEnemy` игра не разрешает менять goodwill. RHF отдельно ведёт сохраняемую внутреннюю реакцию; диалог честно объясняет, где был реальный спад goodwill, где только RHF. Отрицательная внутренняя оценка повышает враждебность.
12. Нет нужд mood → выдача через `RHFMoralResponse.GivePublicCrueltyThoughts` связана с подтверждённым событием и раскрытием, если есть подходящий WCE2-принцип/кровожадность; диагностика показывает число получивших. Нельзя получить этот эффект за просто ранение без обвинения.
13. Команды вперемешку → разделены `RHF - ТЕСТЫ | РЕЙДЫ`, `... | ПЛЕННИКИ`, `... | ДИАГНОСТИКА`, девять `DebugActionType.ToolMap` для тестовых рангов 0–8 (клик на карте), расширенная диагностика хирургических хуков и тестовая фиктивная запись.
14. Сборка часто падала → workflow включает Python-контракты, но после Push обязательна настоящая компиляция. В предыдущих версиях возникали конкретные ошибки API RimWorld 1.7. Никогда не объявлять релиз проверенным до зелёного GitHub Actions и игрового теста.

## Структура

`RaidersHaveFamilies/Source/RHFDialogue.cs` — ветки радиодиалога.
`RHFPatches.cs` — Harmony перехват ванильного диалога фракций, прибытия/ареста/выхода, хирургических событий.
`RHFHostageSystems.cs` — реестр, условия выкупа, оценка рангов/здоровья, раскрытие, дипломатия, награда.
`RHFDebugActions.cs` — тестовые команды.
`RHFRankUI.cs`, `RHFRanks.cs` — интерфейс и ранги v0.4.0.
`RHFPreceptNotes.cs` — описание существующих принципов в Ideology (интегрирован ранее подготовленный патч v0.3.2).
`RHFPoliticalReputation.cs` — изменение vanilla goodwill + внутренней реакции для permanentEnemy.
`RHFWCERegistry.cs`, `WCE2_EXACT_DEFS_AUDIT.md` — точные рецепты WCE2 из пользовательского архива 1.6.
`tests/rhf_050_diplomacy.py` — дополнительные статические контракты.

## Открытые ограничения

Полный VIP-эскорт и выдача серебра у ног охраны, полноценная капсульная экстракция, уникальные квесты спасения из поселений, все экзотические хирургические воркеры, каннибализм как RHF-публичность и реальная тактическая коалиция **не завершены**. WCE2 пользователя построен до 1.6; работает ли его DLL в 1.7 — проверяется отдельно. Не обещать гарантии совместимости и максимального TPS без игры/профайлера.


## R0.6.0: пользовательская проверка и новая система

Пользователь НИ ОДИН из пакетов с начала тестов (0.3.2 / 0.4.0 / 0.5.0) НЕ УСТАНАВЛИВАЛ. Следовательно, распространять **только полный объединённый ZIP 0.6.0**, не просить ставить старые патчи.

Последняя жалоба: отладочные спасатели не появились; причина по исходникам — debug добавлял RaidEnemy в очередь через 150 тиков, а на момент отложенного запуска возможно молчаливое отклонение инцидента. Также нужны коалиции 3+ сторон, наёмники без собственных пленников, комбинированные удары как одной фракции, так и нескольких.

Реализация: `RHFStrikeParty` со штатной сериализацией, роли Rescue/Diversion/Vengeance, активное связывание спавнящихся пешек с вызываемой именно сейчас партией; `ForceDeployNow` вызывает `IncidentDefOf.RaidEnemy.Worker.TryExecute`, возвращает отказ и пытается перейти на обычный штурм. В натуральных операциях — 1..4 фракции-заявителя плюс опциональный hired executor, общий бюджет угрозы, сохранение независимого времени подготовки (5000 тиков). В debug добавлены тесты single combined / coalition 3+ / hired diversion / combined mixed, VIP других фракций кликом на карту, диагностика рейдов. Сохранено обратное чтение старых операций без дублирования события.

**Не решено:** взаимная враждебность участников разных модовых фракций (могут атаковать друг друга), гарантии генерации рейда для фракций без raid pawn group maker, полноценный transport pod и перевозка бессознательного NPC; игровая проверка, запуск на GitHub и TPS не проведены.
