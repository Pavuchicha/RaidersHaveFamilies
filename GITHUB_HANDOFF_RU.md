# Пакет передачи — Raiders Have Families 0.3.0

Дата: 2026-11-21. Целевая игра: RimWorld 1.7. Пакет: исходный код, **не готовая DLL**.

## Важнейший факт о предыдущем падении CI

GitHub Actions run `44899885155` (https://github.com/Pavuchicha/RaidersHaveFamilies/actions/runs/44899885155) завершился failure на `dotnet build`.

Точное сообщение: `RHFPatches.cs(65,41): error CS1503: Argument 6: cannot convert from 'Verse.TraverseMode' to 'bool'`.

**Исправление:** вызов `myPawn.CanReach(__instance, PathEndMode.InteractionCell, Danger.Some)` без старых шестого/седьмого аргументов. Прежний архив 0.2.0 НЕ переиспользовать. Для восстановления именно 0.2.0 имеется отдельный малый ZIP-патч.

## Что реально добавлено

- Девять рангов 0–8; миграция старого сохранённого `Importance`; нелинейная цена, масштаб военного ответа.
- Больше связей среди одной группы, повторное использование известных сгенерированных родственников, лимиты на создание и сохранение.
- Сохранённое политическое давление на фракции с фиксированной враждой, встречные предложения, срок инициативных предложений и последствия игнорирования.
- Массовое удержание шести обычных пленников одной фракции способно активировать освобождение даже без VIP.
- Планировщик возмездия (высокие очки угрозы с потолком, ветер/стратегии, возможно осада и drop, дополнительные животные для низкотехнологичных фракций) и rescue controller с конкретными Pawn targets. Команды только по расписанию 300 тиков, не на каждом тике.
- Спонсор и исполнитель могут быть разными фракциями, включая армию-наёмника. Два спонсора могут финансировать одну спасательную группу. Конкретные межфракционные соглашения не меняют отношения фракций глобально.
- Командная логика проникновения, атак стен/дверей, 2 ограниченных зарядов (если достаточно безопасно для пленника), освобождения, эвакуации, fallback по таймеру.
- Подготовка условного лагерного комплекса из стали, размещение капсулы и стартовой площадки, выход VIP через игровую механику (ещё не real job-driver/skyfaller).
- Полная XML-инвентаризация загруженного архивного WCE2 1.6 — 60 операций. Действительные harmful operations и restorative/reversal разграничены, событие хирургии после `ApplyOnPawn`.
- Заметки и тесты по статике.

## Серьёзные ограничения / не выдавать за готовое

1. В рабочем окружении нет .NET 10 и RimWorld DLL. **Новый код не скомпилирован**. Статические Python/XML проверки — только базовая валидация. GitHub Actions обязателен.
2. **Особенно опасный для игрового теста узел:** `RHFOperationController` отрывает спасателей от ванильного Lord и выдаёт прямые задания. Нужно проверить спавн, должности, job conflicts, подрыв, освобождение, путь выхода, сохранение во время операции. При любых отказах корректировать причину; не подавлять ошибку.
3. Капсулы создаются через длительную по игровому времени постройку и затрату физической стали, но без собственного `JobDriver` инженерного строительства, без настоящей анимации `Skyfaller/TransportPodLeaving`. Это ПРОТОТИП, не заявлять финальной реализацией.
4. Квест спасения из иностранного поселения и физический сопровождающий при передаче за выкуп пока отсутствуют.
5. Полнота поддержки модовых рас, социальных типов, романтических механик, обилия протезов, идеологий и HostageTaker не подтверждена.
6. WCE2 из присланного ZIP поддерживает только 1.1–1.6, имеет DLL в `1.6/Assemblies`. Проверить возможность совместной загрузки на 1.7, не копировать и не перепаковывать его бинарники.
7. Следующий практический шаг — CI compile error triage, затем запуск RimWorld 1.7 с чистым логом и profiler. Лишь после стабильной компиляции — отдельный полноценный AI освобождения пленников из поселений, convoy ransom, air evacuation, cannibal/crimes tracking.

## Качество и производительность

- Система устроена событийно. Проверки активного операции каждые 300 тиков. Всего максимум 4 операции на карту, 96 бойцов в одной спецгруппе, 14 заказов за цикл.
- В обычное время эвент-очереди пустые, повседневный TPS должен практически не меняться; **измерений нет**.
- Беречь сохранения: не удалять ванильные/чужие world pawns. Изменять только созданные модом world pawns и связи. Не очищать отношение игрока к действующим родственникам.
