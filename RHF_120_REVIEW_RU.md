# RHF v0.12.0 — отчёт о доработке и честная приёмка

**21.11.2026 · статус: ИСХОДНИКИ / НЕ ПОДТВЕРЖДЕНО В ИГРЕ.** Полная накопительная поставка начиная с ранних версий до v0.11.0 включительно. ZIP содержит проект GitHub Desktop, а не готовую DLL. Изменения в старые сохранения вносятся без сброса истории заложников; гарантии совместимости нет, нужен резервный сейв.

## Новый функционал в коде

1. **Вербовка чужого пленника.** Harmony отслеживает штатный `RecruitUtility.Recruit` и `Pawn.SetFaction(Faction, Pawn)`, различает передачу в колонию и действительную вербовку. При высоком ранге исходной фракции может быть запланирована карательная операция; охотники получают целью конкретного завербованного персонажа. Самостоятельное наблюдение за ключевой личностью реального графа связей ещё не добавлено.
2. **Обращение в новую идеологию.** Переход выявляется по `Pawn_IdeoTracker.SetIdeo` и сохраняет `OriginalIdeo`/`ConvertedIdeo`. В радиопереговорах появляется новое действие только после реального изменения веры. При докладе всем присутствующим на карте колонии свободным колонистам новой веры выдаётся положительное RHF-воспоминание, бывшей веры — отрицательное. Воспоминания не выдаются за одно только обращение, не начисляются повторно после одинакового доклада; по 3 ступени в зависимости от значимости цели, 5 дней. Случай смены веры по истории старого сейва до установки v0.12 необходимо отдельно проверять.
3. **Пленные, обращённые в рабство.** Запись RHF сохраняется, цели поискового/спасательного рейда включают рабов, а десант ищет площадку в пределах радиуса пяти клеток от конкретного раба. Если такой площадки нет, используется ближайшая физически пригодная альтернативная точка — не случайная середина карты. Иные исключения для рабства не вводятся.
4. **Миссии:** сохраняемые доктрины PrisonBreakout, InfiltrationAndExit, FortifiedVipExtraction, RescueAndReprisal, PunitiveAssault, TargetedTraitorHunt, SiegeAndRaze, RescueThenAssault. Отдельные компоненты — вход, охраняемый объект, задача, отход, дальнейший штурм — комбинируются в ограниченном количестве предопределённых профилей. Это не «бесконечное множество» свободных планов.
5. **VIP-эвакуация:** опытная фаза доступа в комнату, физически построенные стальные баррикады (до двух, ограниченно, при наличии материала), полевой корпус и пусковая. После подхода пленника к капсуле вызывается реальный `ActiveTransporter` и формируется `FlyShipLeaving` с объектом пленника внутри, а не прямой `vip.ExitMap()`. Сразу при неудаче план отходит к выносу по земле; не гарантируется сохранность VIP при несовместимости модовых загрузчиков/воздушных транспортов.
6. **Стройматериалы:** источник бюджета полевой капсулы привязан к общей стоимости операции, а не генерируется бесплатно дополнительно к полной армии. Требуемая сумма резервируется из очков рейда, при недостатке денег выбирается пешее спасение; фактические предметы всё ещё доставляются абстрактно в момент подготовки, а не грузовиками.
7. **Иные рейды:** каратели получают ограниченную охоту на конкретного завербованного VIP и выбирают реальные цели разрушения — турели, энергию, производственную инфраструктуру. Поддержаны переключение на карательную фазу после спасения и многоотрядные комбинации. Штатные AI и генераторы других модов остаются задействованы.
8. **Коалиции:** до пяти отдельных партий; отсутствие собственных пленников не запрещает наёмные войска. Полная временная совместимость исторически враждующих между собой участников НЕ реализована.

## Что сознательно НЕ объявлено готовым

- Не внедрён полностью собственный RimWorld `LordJob`/`LordToil` для каждой из всех операций. Нет гарантии, что рейдеры всегда грамотно прикрывают, маневрируют и оставляют охрану у капсулы. Нет общего планировщика укрытий/огня.
- Стены строятся ограниченным действием сапёра после подхода, а не полноценными `JobDriver_Construct` с рабочими приоритетами, маршрутом носильщиков и выполненными промежуточными этапами.
- Гарантированный вылет VIP в капсуле (и его восстановление после перезагрузки) не проверен; вызовы skyfaller не компилировались и не исполнялись локально.
- Полная многоступенчатая генеалогия пришедших пешек, квесты на захват пленников из враждебных поселений, продвинутые коалиции взаимно враждующих фракций, полная система военного снабжения/доктрин фракций и CE-интеграция остаются в очереди.
- Механика WCE2-операций и автоматическое создание семей по-прежнему требуют самостоятельных игровых тестов на скринах/сейвах пользователя. Прошлые версии не давали здесь надёжного результата.

## Результаты проверок

- Все **20 Python структурных / лексических / XML-тестов** в `tests/` проходят локально.
- Новые v0.12 контракты отслеживают перехваты конверсии/вербовки, сериализацию, правило slave landing, физический skyfaller, исключение прямого ExitMap, бюджет капсулы и фазность миссии.
- **Критично: .NET/C# не собраны в контейнере; зелёный GitHub Actions пока отсутствует.** Единственный способ подтвердить API — новое задание в GitHub Actions после Push origin.
- TPS не замерен; периодический контроль ограничен количеством бойцов/целей и интервалами. Нет гарантии производительности в больших модпаках.

## Обязательные игровые сценарии v0.12.0

1. Сохранить копию сейва. Начать тест на v0.12 после зелёной GitHub Actions. В Console debug открыть `26 — Аудит вербовки и смены идеологий` и `27 — Аудит боевой доктрины / охоты / капсул`.
2. Взять пленника ранга 6–8, **сначала обратить его идеологию**, затем выбрать через штатную радиосвязь «Сообщить об обращении». Проверить мысль у верующих новой/старой идеологии, отсутствие повторного начисления, сохранение после загрузки сейва.
3. Взять другого VIP, **завербовать штатным взаимодействием пленника**. Проверить, что RHF записал вербовку (а не просто появление колониста), сохранил исходную фракцию и при возможном возмездии выбрал именно этого колониста целью охоты.
4. Превратить другого пленника в раба, отправить десантный рейд спасателей. Вызвать аудит: проверить радиус до пяти клеток, если есть допустимая клетка, и реальное освобождение с последующим организованным отходом.
5. В тесте VIP-капсулы проверить настоящее строительство двух баррикад и расход стали, физическое помещение VIP в активный контейнер, отсутствие пустого skyfaller и то, что пешка не удаляется бесследно. Повторить с закрытой толстой каменной крышей: никакого бесплатного проникновения.
6. Проверить доктрины Vengeance/TargetedTraitorHunt/SiegeAndRaze/RescueThenAssault и их реальное поведение при погибших/убегающих рейдерах. Провести тест на CE и модовой фракции.
7. Измерить TPS в одинаковом сейве на скоростях ×2/×3 с RHF и без, отдельно для комбинации 5 партий; проверь лог на C# exceptions.
8. Повторить старые P0-провалы — семьи рейдеров без dev-команд и WCE2 отрезание уха со списком документированных операций. Нет результатов = задача не закрыта.

## Реестр всех прошлых требований

См. **`REQUIREMENTS_AUDIT_MASTER_RU.md`**. Для каждого пункта есть степень реализации, недостающая часть и способ приёмки. Основные P0/P1/P2 указаны там. Ближайший приоритет — реальные игровые тесты, затем полноценный отдельный `LordJob`/`LordToil` тактического ИИ, а не новые декоративные реплики.

**Детальная концепция всех отдельных/составных типов рейдов:** `TACTICAL_DOCTRINE_DESIGN_RU.md`, с честными статусами реализованного.
